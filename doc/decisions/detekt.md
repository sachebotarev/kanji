# Статический анализ Kotlin: detekt

Принято: 2 ноября 2026 года.

## Подключение

Используется стабильный **detekt 1.23.8**, версия закреплена в `gradle/libs.versions.toml`. Корневые задачи `detekt` и `detektBaseline` запускают CLI через `JavaExec`, как описано в [официальной инструкции](https://detekt.dev/docs/1.23.8/gettingstarted/gradletask/).

Проект использует Gradle 9.6, AGP 9.4.1 и Kotlin 2.2.10. В [таблице совместимости detekt](https://detekt.dev/docs/1.23.8/introduction/compatibility/) для 1.23.8 указаны Gradle 8.12.1, AGP 8.8.1 и Kotlin 2.0.21. Запуск отдельного CLI изолирует зависимости анализатора от плагинов сборки и не требует применения Android/Kotlin-интеграции detekt. Предварительные версии detekt 2.0 не используются.

Анализируются `.kt` и `.kts` в `src/` всех Gradle-модулей с собственным build-файлом, включая JVM-тесты и Android-тесты. Новые модули подхватываются автоматически. Генерируемые файлы в `build/`, Gradle-скрипты и учебные данные не входят в область анализа.

Анализ выполняется **без type resolution**: правила, требующие classpath компилируемого приложения, не работают. CLI содержит собственный анализатор Kotlin 2.0.21; успешный прогон текущих исходников не гарантирует поддержку будущего синтаксиса Kotlin. detekt дополняет Android Lint и тесты. Правила переводов, ресурсов и русского fallback проверяются существующими средствами проекта.

## Правила и baseline

`config/detekt/detekt.yml` дополняет стандартные правила detekt, включает проверку корректности конфигурации и адаптирует правила для Compose по [рекомендациям detekt](https://detekt.dev/docs/1.23.8/introduction/compose/): имена `@Composable`, приватные `@Preview`, константы, числовые свойства и параметры со значениями по умолчанию. Правило `TooGenericExceptionCaught` сохраняет строгость для бизнес-логики и утилит; граничные методы UI-состояния (ViewModels/Loader) используют целевой `@Suppress("TooGenericExceptionCaught")` с обязательным предварительным пробросом `CancellationException`.

`config/detekt/baseline.xml` фиксирует существующие замечания при подключении. Это список технического долга, а не подтверждение исправности кода. Новое замечание за пределами baseline завершает задачу ошибкой. Обычные проверки не обновляют baseline; массовое обновление ради зелёной сборки недопустимо. При исправлении долга соответствующие записи следует удалять.

## Команды

```bash
./gradlew detekt
./gradlew detektAll
./gradlew :app:check
```

Корневой `check` и `check` каждого модуля зависят от единой задачи `:detekt`; за один запуск Gradle анализ выполняется один раз. `assembleDebug` и установка приложения не запускают анализ автоматически.

Отчёты создаются в `build/reports/detekt/`: `detekt.html`, `detekt.sarif`, `detekt.xml`. Исходники, конфигурация и baseline учитываются как входы задачи, отчёты — как выходы. Отчёты остаются локальными build-артефактами.

`detektAll` выполняет полный аудит без baseline и сохраняет отчёты отдельно в `build/reports/detekt-all/`. При наличии замечаний команда завершается ошибкой; это ожидаемый результат аудита. В `check` входит только `detekt`, который проверяет новые замечания. [Результаты первого аудита](../verification/detekt/2026-11-02.md).

Только для осознанного пересмотра списка текущих замечаний:

```bash
./gradlew detektBaseline
```

Изменения baseline проверяются в Git вместе с изменением кода или правил. В окружении должны быть настроены JDK и Android SDK так же, как для обычной сборки.
