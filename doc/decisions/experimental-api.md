# Явное разрешение на experimental API

По умолчанию применяются стабильные API. Каждое новое применение experimental/preview функции, типа и соответствующего opt-in требует предварительного явного разрешения пользователя. Разрешение должно определять API и область использования. Общее поручение разработать экран, исправить ошибку или следовать примеру из навыка не является разрешением.

Разрешение действует только в зафиксированных границах. Новые experimental API, перенос в другой модуль и расширение назначения согласуются отдельно. Уже разрешённое применение не требует повторного согласования, пока API и область не меняются. Этот порядок не разрешает нестабильные версии библиотек или экспериментальные флаги языка.

## Действующее разрешение

| API | Область | Основание |
| --- | --- | --- |
| Material 3 `TopAppBarDefaults.enterAlwaysScrollBehavior`, `TopAppBarScrollBehavior` и необходимые для них типы состояния, `ExperimentalMaterial3Api` opt-in | Существующая скрываемая панель фильтров каталога в `:feature:catalog`, `CatalogScreen.kt` и `EnterAlwaysPanel` | 2 ноября 2026 года пользователь явно подтвердил ранее принятое решение использовать experimental в этом механизме |

Наличие opt-in в коде само по себе не является разрешением на добавление других experimental вызовов. При изменении статуса API в используемой версии библиотеки необходимо проверить возможность убрать ненужный opt-in.
