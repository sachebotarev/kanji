# Три независимые проверки кандзи

19 октября 2026 года. Реализуется по согласованию с пользователем.

- Читаемость: первый кандидат японского ML Kit Digital Ink Recognition должен точно совпасть с заданным знаком. Альтернативы и подсказка целевого текста не используются. Ключ `u<hex>` преобразуется адаптером в Unicode. Модель автоматически загружается при запуске приложения без диалогов подтверждения и прогресса. При ошибке показывается сообщение о повторной загрузке через кнопку статуса в настройках. Без модели читаемость выключена, включение недоступно и сопровождается пояснением. См. [загрузка модели](../implementation/japanese-model.md). На загрузку отведено 60 секунд; сама проверка модель автоматически не скачивает; дальнейшее распознавание локальное. Для загрузки добавлено разрешение INTERNET. Время ожидания ограничено 30 секундами; отсутствие модели/ошибка/таймаут дают «Недоступно», а не неверное написание. Версия SDK 19.0.0 проверена по [официальной документации](https://developers.google.com/ml-kit/vision/digital-ink-recognition/android). Время между чертами UI-PAD не хранит, поэтому адаптер передаёт точки без времени.
- Форма: существующий ShapeKanjiChecker, пороги и компенсации без изменения; в приложении порядок и направление принудительно отключены в его снимке конфигурации. Крючки, количество черт и словарь остаются частью формы.
- Порядок и направление: StrokeWritingChecker использует исходную геометрию, прежнее сопоставление и прежние две проверки; не зависит от принятия формы. При недостатке черт — Incomplete, при лишних — ошибка количества. Низкоуровневые настройки порядка/направления у ShapeMatcher оставлены для совместимости диагностических тестов.

CombinedKanjiChecker в чистом domain запускает включённые провайдеры параллельно с единым снимком настроек. Отказ одного не теряет результаты остальных; отмена распространяется наружу. Принятие возможно только при Correct всех включённых. Если все выключены — Incomplete («Без проверки»), автоматического принятия нет. CheckReport содержит отдельные результаты и диагностику формы. Механизм ревизий ViewModel защищает от устаревших ответов и повторно проверяет ввод после изменения настроек.

Все три проверки изначально включены. Их выключатели сохраняются через SavedStateHandle отдельно от прежнего числового профиля. Это восстановление процесса/конфигурации, не постоянное хранилище настроек.

Временные компактные индикаторы «Читаемость», «Форма», «Черты» для выбранной ячейки находятся над полем вместо номера знака и общего «Верно/Неверно». Три равных скруглённых блока используют зелёный фон/текст при успехе, красный при ошибке или недоступности, нейтральный при ожидании, неполном вводе, проверке и отключении. Галочки, крестики и кружки убраны; stateDescription продолжает явно озвучивать статус. Читаемость всегда показывает полученный от распознавателя знак, включая несовпадение с заданным; форма — округлённый процент соответствия, черты — число завершённых черт в выбранной ячейке (обновляется после ввода, очистки и отмены). Пока значение отсутствует — тире, при проверке — многоточие. Макет: [цветные индикаторы](../design/check-indicators-color-concept.png). Процент передаётся типизированным полем CheckReport.matchPercent независимо от включения debug-диагностики. Таймер сохранён. Отдельная стрелка следующего знака убрана; ячейки выбираются в верхнем ряду. При ошибке третьего чекера под блоками выводится короткая причина: нарушенный порядок (номера позиций ввода), обратное направление (номера эталонных черт) или фактическое/ожидаемое число черт. В настройках — три независимых выбора. Итоговый дизайн отложен до следующей сессии. Пока идёт запрос, отображается «Проверяется»; результаты появляются общим снимком после завершения всех провайдеров.

Распознавание получает порядок исходных черт, поэтому читаемость статистически может зависеть от порядка даже при выключенном третьем чекере.

Актуальный интерфейс по согласованному v9: [реализация рабочего экрана](../implementation/practice-workspace.md). Проверки — компактные двухстрочные значения над холстом, подробности — отдельными диалогами по нажатию; строка ошибок под индикаторами заменена диалогом.
