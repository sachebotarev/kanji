## GitHub Pages

Workflow `.github/workflows/privacy-pages.yml` (**Publish privacy policy**) публикует сайт приложения и политику. Jekyll собирает только `doc/legal`, исключая этот служебный README. Русская политика публикуется как `index.html`, английская — как `privacy-policy.en.html`. Тексты Markdown являются единственным источником политик. Остальная документация проекта не входит в артефакт Pages.

### Страница приложения · SHARED.04

- Английская: `https://sachebotarev.github.io/kanji/app/en/`.

Политика содержит ссылку на приложение и описание хостинга GitHub Pages; [официальная документация](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection) указывает регистрацию IP-адресов посетителей хостингом.

Главный баннер сочетает маскот и реальные PNG карточки кандзи 山 из Android в светлой теме: `assets/kanji-light-ru.png` и `assets/kanji-light-en.png`. Оба кадра сняты с физического Pixel 10 Pro в исходных 1080 × 2410, без изменения разрешения, обрезки или перерисовки. Смена языка выбирает соответствующий кадр; отсутствующий английский перевод учебного значения отображается по русскому fallback приложения. Изображение масштабируется пропорционально через CSS `width` / `height:auto`; ссылка открывает полный оригинал в новой вкладке. Кот — отдельный декоративный PNG рядом с кадром; знак, перевод и чтения не закрываются.
- Приложение опубликовано: `https://play.google.com/store/apps/details?id=ru.mobui.kanji` возвращает HTTP 200. Ссылка задана единожды полем `store_url` в `_config.yml`; из неё формируются кнопки установки в главном баннере и блоке доступности в обеих локалях. Возможности сверены с README и реализацией.

Оформление использует зелёный бренд приложения (`#1E6A4B`), светлую бумагу (`#F7FAF5`), тёмные чернила (`#193C2E`), спокойный текст (`#52645A`), светло-зелёный (`#E5EFDF`) и бумажный акцент (`#F1E6CF`). Системный Trebuchet MS/Arial поддерживает русский без внешних загрузок. Японские символы в баннере являются частью реального скриншота. Композиция: крупный заголовок и кнопка установки рядом со светлым скриншотом карточки и котом, три возможности, последовательность обучения, автономность, доступность и контакты. Существующая палитра и маскот определяют визуальный стиль.

Использованы штатные механизмы Jekyll: Liquid, `_data`, layout и permalink; собственный генератор переводов не вводится. Context7 недоступен, механизм сборки сверен с официальным workflow GitHub Pages, перечисленным ниже. Новых библиотек и experimental API нет. Композиция и CSS относятся только к публичной странице; Android-код не меняется. Для съёмки временно включалась светлая системная тема; после съёмки восстановлены тёмная тема, исходный список языков приложения `[]`, обычная строка состояния и `sysui_demo_allowed=0`. К стилям добавляется параметр времени сборки Jekyll, чтобы браузер получал обновлённый CSS после публикации. [Проверка релизной страницы](../verification/pages/release/README.md).

Для первого размещения:

1. В репозитории `sachebotarev/kanji` открыть **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Закоммитить и отправить файлы политики и workflow в `main`.
3. Дождаться успешного workflow **Publish privacy policy** во вкладке **Actions**. При необходимости запустить его через **Run workflow**.
4. Проверить обе страницы без входа в GitHub. Ожидаемые адреса после успешной публикации:
   - Русский / URL для Google Play: `https://sachebotarev.github.io/kanji/`.
   - Английский: `https://sachebotarev.github.io/kanji/privacy-policy.en.html`.

При смене имени репозитория или пользовательского домена обновить `url` и `baseurl` в `_config.yml` и `public_url` записи `SHARED.04` в реестре экранов. Доступность Pages для закрытого репозитория зависит от тарифа GitHub.

Используется штатная сборка GitHub Pages через Jekyll и официальные Actions из [документации GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages): `checkout@v6`, `configure-pages@v5`, `jekyll-build-pages@v1`, `upload-pages-artifact@v4`, `deploy-pages@v4`. Новых зависимостей Android нет. Результат проверки публикации сайта фиксируется в `doc/verification/`.

## Основания текста

Проверены `app/src/main/AndroidManifest.xml`, `app/src/main/res/xml/backup_rules.xml`, `app/src/main/res/xml/data_extraction_rules.xml`, зависимости приложения, реализация `checker/readability`, локальные репозитории `data/catalogdb` и настройки. ML Kit Digital Ink Recognition подключён в версии **19.0.0**. В существующем объединённом release-манифесте присутствуют `INTERNET` и `ACCESS_NETWORK_STATE`; исходный манифест приложения сам их не объявляет. Готовый объединённый манифест является вспомогательным свидетельством и не заменяет проверку финального AAB.

Распознавание локальное, японская модель загружается через Google. Отдельных рекламных или аналитических SDK в объявлениях зависимостей не обнаружено; это не отменяет диагностику ML Kit. `allowBackup=true`, правила не исключают пользовательскую БД и настройки из системного копирования.

Проверены официальные источники:

- [Требования Google Play к пользовательским данным](https://support.google.com/googleplay/android-developer/answer/10144311?hl=ru): содержание политики, контакт, хранение и удаление, доступность страницы.
- [Раскрытие данных ML Kit](https://developers.google.com/ml-kit/android-data-disclosure): диагностика SDK; источник описывает актуальные SDK, поэтому перед выпуском нужно повторно сверить финальный состав зависимостей.
- [Digital Ink Recognition для Android](https://developers.google.com/ml-kit/vision/digital-ink-recognition/android): документация содержит подключённую версию 19.0.0 и локальное распознавание.
- [Android Auto Backup](https://developer.android.com/identity/data/autobackup): системные копии и восстановление.

Новые API и библиотеки не выбирались и не применялись; Context7 в текущем окружении недоступен, сведения сверены непосредственно с официальными источниками.

## Подготовка к публикации

1. Разместить тексты как общедоступные страницы по постоянным HTTPS-адресам: без входа, географических ограничений и возможности посетителям изменять текст. Google Play требует веб-страницу, а не PDF. При отсутствии перевода показывать русский текст.
2. Указать URL политики в Play Console и добавить доступную ссылку или текст политики в приложение. Этот документ не добавляет интерфейс; соответствующие изменения экрана `SETTINGS` потребуют обновления карты проекта.
3. Заполнить «Безопасность данных» по итоговому AAB и всем SDK. Не выбирать автоматически «данные не собираются»: локальность распознавания не исключает сетевую диагностику. Сопоставить диагностические данные с категориями формы, целями обработки и правилами Google о передаче поставщикам услуг.
4. Сверить возрастную аудиторию в Play Console. Раздел о детях в политике сам по себе не подтверждает соответствие требованиям Families.
5. Перед выпуском проверить актуальность политики относительно финальной сборки, работу публичных ссылок и совпадение русского и английского текстов. Сетевая трассировка, фактические сроки хранения у Google и проверка финального AAB в рамках подготовки текстов не выполнялись.
