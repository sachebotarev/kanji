# «Мой словарь»: предложение экранов

21 октября 2026 года. Статус: предложение для обсуждения, не утверждённая спецификация. Правило происхождения и прав изменения согласовано пользователем: изменять и удалять можно только созданные вручную слова. Остальные предложения экранов остаются на обсуждении. Код приложения не изменён.

## Основа

Изучены актуальные `doc/screens/catalog.md`, `doc/implementation/catalog.md`, `doc/database/words.md`, правила архитектуры и локализации, реализация `CatalogScreen.kt`, `CatalogWidgets.kt`, `Catalog.kt`, `RoomCatalogRepository.kt` и снимок `catalog-refined-dark-word-card.png`.

Сохраняем существующий язык интерфейса: тональные поверхности, скругления 24dp, внешние отступы 20dp, написание и чтение рядом в списке, полный перевод ниже. Длинные выражения и предложения поддерживаются наравне со словами.

## Рекомендуемый вариант А

### Список

Заголовок «Мой словарь», количество записей, поиск по написанию, чтению и отображаемому переводу. Общая строка слова как в каталоге. Кнопка «Добавить слово» внизу справа. Начальный порядок — последние добавленные первыми; для этого требуется сохранять время добавления личной связи, сейчас такого поля нет. Фильтры глав и учебников сюда не переносим. Фильтр по входящему в написание кандзи можно добавить позднее: это другая семантика, чем учебная привязка каталога.

Пустой словарь: пояснение и действие «Добавить первое слово». Пустой поиск: сообщение и очистка запроса. Отдельные состояния загрузки, ошибки с повтором. При возвращении сохраняются поиск и позиция списка; после создания открывается сохранённое слово.

### Общая страница слова

Одинаковые блоки для каталога и личного словаря: написание, полное чтение, локализованный перевод; части чтения при наличии; кандзи в написании; учебные привязки при наличии. Пустые разделы скрыты. Ссылки на кандзи ведут в существующий просмотр справочника.

Каталог: только просмотр. В «Моём словаре» кнопка редактирования и удаление доступны только для слов с признаком ручного создания. Для остальных слов эти действия скрыты. Возможности передаются явным состоянием действий; решение о доступности принимает внешний слой. Общие виджеты не проверяют источник по его переведённому названию и не выполняют навигацию самостоятельно.

### Общая форма создания и редактирования

Различаются заголовок («Новое слово» / «Редактирование слова»), исходные значения и операция сохранения. Общие поля: написание, полное чтение, список переводов с выбранным языком. В русской локали первая строка перевода — русский, в английской — английский; можно явно добавить русский или другой язык. Отсутствие русского не заменяется английским автоматически: просмотр использует существующий fallback и явное отсутствие перевода. Точные обязательные поля согласовать перед реализацией; предлагается требовать написание, чтение и хотя бы один непустой перевод.

Язык каждого перевода виден явно; отсутствующий перевод не заполняется резервным текстом в редактируемом поле. Хранилище — строки `words_translations` с `language_tag`, без колонок на каждый язык. Повтор языка в форме исключён. Длинные значения допускают переносы. Учебные привязки и автоматически найденные кандзи не являются обязательными полями формы. Части чтения не генерируются догадками; изменение написания/чтения требует проверки существующего разбиения.

Сохранение защищено от повторного нажатия. Ошибки показываются у полей, ошибка записи сохраняет введённое. Назад при изменённой форме открывает диалог «Сохранить / Не сохранять / Продолжить редактирование»; сохранение доступно после валидации. Черновик восстанавливается при пересоздании экрана.

### Удаление

Действие «Удалить слово» доступно только для созданной вручную записи → диалог с написанием слова → возврат в список после успешной операции. При ошибке карточка остаётся доступна, сообщение предлагает повтор. Для слов каталога запрещено и удаление самой записи, и удаление из личного списка в рамках этого сценария. Способ удаления ручной записи (физическое удаление или архивирование) определяется при реализации с учётом связей и будущей статистики.

## Переиспользование и границы

Существующие `WordRow`, `WordList`, `WordDetail`, `CatalogSearch`, информационные панели и секции дают основу. Сейчас часть компонентов `private`/`internal` в `:feature:catalog`, а `WordDetail` принимает целиком `CatalogUiState` и `CatalogActions`: прямое использование из другого feature создаст запрещённую зависимость.

Предлагается выделить содержательные компоненты в `:core:wordui`: `WordList`, `WordRow`, `WordDetailsContent`, `WordSummaryCard`, секции чтения/связей, `WordEditorForm` и блок переводов. Базовые поля, поиск и поверхности остаются в `:core:designsystem`, когда появляются реальные общие потребители. Имена предварительные. Компоненты получают узкие модели состояния, callbacks и Modifier; в них нет ViewModel, репозитория и маршрутов. Карточки кандзи и источников также передают клики наружу.

`:feature:catalog` и будущий `:feature:dictionary` используют общие компоненты; приложение связывает переходы. Экран формы один для создания/изменения. Не следует превращать каталог в универсальный экран с большим числом флагов или переносить учебную модель в дизайн-систему.

## Ограничения данных перед реализацией

1. `CatalogRepository.load()` возвращает закэшированный снимок; текущий адаптер исключает personal-источники и их связи. Для CRUD нужен наблюдаемый контракт личного словаря и обновление деталей после записи.
2. По документации `words` уникальны по написанию и чтению и общие для источников. При совпадении создания используется существующее слово и новая личная связь; повторная личная связь не создаётся. Совпадение с каталогом не делает существующее слово ручным и не разрешает перезапись его перевода. Повторное создание ручного слова также не создаёт дубль.
3. Согласовано: у слова хранится независимый от языка признак происхождения, например `is_user_created`. Для поставляемых слов он ложный, для новой записи, созданной вручную, — истинный. Принадлежность личному источнику и знак ID не заменяют этот признак. Только ручные слова разрешено изменять и удалять; проверка обязательна в операциях записи, а не только в UI. Ручная запись не должна автоматически становиться поставляемой при совпадении в будущем импорте: конфликт требует явного разрешения, без смены происхождения и потери пользовательских данных.
4. Установщик сохраняет личные данные, но может обновлять поставляемые записи. Правила владения должны защищать пользовательские изменения и переводы от перезаписи. Отрицательные ID уже предусмотрены для пользовательских записей.

## Последующая проверка реализации

Создание → просмотр → изменение → удаление; совпадение с каталогом и повторное добавление; сохранность учебных данных; ошибка записи и повтор; возврат/восстановление формы; русский и английский UI, fallback и отсутствие перевода; длинное предложение и крупный шрифт. Проверки поведения, сборка и lint выполняются при реализации.
