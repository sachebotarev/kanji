## 🔴 КРИТИЧЕСКИЕ (Bug / Data Loss Risk)

### 1. `RoomCatalogRepository.saveWord()` — гонка через `load()` внутри транзакции

- **Файл:** `data/catalogdb/src/main/kotlin/ru/mobui/kanji/data/catalog/RoomCatalogRepository.kt:58`
- **Проблема:** `saveWord()` вызывает `load()` (чтение из БД) **внутри** `withTransaction { ... }`. `load()` вызывает `CatalogInstaller.install()` который пишет данные. Чтение + запись внутри одной транзакции — антипаттерн Room. Если `install()` упадёт (например, каталог повреждён), вся транзакция откатывается, включая пользовательское слово.
- **Исправление:** Вынести `load()` до `mutex.withLock { ... }` или использовать отдельный поток чтения.

```kotlin
// ПЕРЕД withTransaction:
load()
// ПОТОМ:
mutex.withLock {
    database.withTransaction { ... }
}
```

### 2. `DigitalInkKanjiChecker` — создание `DigitalInkRecognizer` на каждый `checkWithDetails()`

- **Файл:** `checker/readability/src/main/kotlin/ru/mobui/kanji/checker/readability/DigitalInkKanjiChecker.kt:72`
- **Проблема:** `getRecognizer()` создаёт новый клиент на каждый вызов если `recognizer` уже `null`. `DigitalInkRecognitionModel` создаётся **каждый раз** в `checkWithDetails()` (строка 47), что дорого.
- **Исправление:** Кэшировать `DigitalInkRecognitionModel` аналогично `recognizer`. Добавить `@Volatile private var cachedModel: DigitalInkRecognitionModel?`.

### 3. `KanjiApplication` — поток `persistenceScope` не завершается

- **Файл:** `app/src/main/java/ru/mobui/kanji/KanjiApplication.kt:15`
- **Проблема:** `CoroutineScope(SupervisorJob() + Dispatchers.Main.immediate)` создаётся при `onCreate()` и никогда не отменяется. Это утечка корутин на время жизни приложения — допустимо для Application-уровня, но документировать нужно.
- **Исправление:** Добавить `onTerminate()` с `persistenceScope.cancel()` и задокументировать.

## 🟡 СРЕДНИЕ (Architecture / Maintainability)

### 4. `MainActivity` — монолитный UI-контроллер, 200+ строк

- **Файл:** `app/src/main/java/ru/mobui/kanji/MainActivity.kt` (весь файл)
- **Проблема:** Содержит `AppDestination` enum, `AppModels`, `DemoPracticeGraph`, `AppUiContext`, 6 `@Composable` навигационных функций, `PracticeSummary`, `createTask()`, `createModels()`, `createPracticeGraph()`, `createChecker()`. Все эти классы `internal` и привязаны к `MainActivity` — это нарушает принцип единой ответственности. `createTask()` хардкодит 4 кандзи (`eeg-0`…`eeg-3`).
- **Исправление:** 
  1. Вынести `AppUiContext`, `AppModels`, `DemoPracticeGraph` в отдельный файл `app-navigation.kt`.
  2. Вынести 6 навигационных `@Composable` в `app-routing.kt`.
  3. Переместить `PracticeSummary` в `feature/practice/`.
  4. Переместить `createTask()` в тестовый модуль.

### 5. `MainActivity.createChecker()` — асимметрия создания чекеров

- **Файл:** `app/src/main/java/ru/mobui/kanji/MainActivity.kt:108`
- **Проблема:** `shape` и `writing` чекеры создаются через лямбду `(RecognitionSettings) -> KanjiChecker`, а `readability` — напрямую. `shape` создаётся заново на каждую проверку, `writing` — один раз.
- **Исправление:** Создать все три чекера один раз в `KanjiApplication` и передавать напрямую в `CombinedKanjiChecker`.

### 6. `CatalogInstaller.install()` — полное перезаписывание каталога

- **Файл:** `data/catalogdb/src/main/kotlin/ru/mobui/kanji/data/catalog/CatalogInstaller.kt:47`
- **Проблема:** `clearLinks()`, `clearPlacements()`, `clearReadings()`, `clearMeanings()` — полная очистка всех таблиц перед вставкой. При крупном каталоге (тысячи записей) это длительная транзакция, блокирующая UI.
- **Исправление:** Разбить на несколько транзакций или использовать batch-вставку с инкрементальным обновлением. Добавить `coroutineContext.ensureActive()` между batch-операциями.

### 7. `PracticeViewModel` — `CheckCoordinator` инкапсулирует много состояния

- **Файл:** `feature/practice/src/main/kotlin/ru/mobui/kanji/feature/practice/PracticeViewModel.kt:225`
- **Проблема:** `CheckCoordinator` хранит `generation`, `job`, `failures`, `revisions`. Он мутируется из `scheduleCheck()` и читается из `publish()`. Нет явной синхронизации — работает через `viewModelScope.launch` и проверку `generation`, что корректно, но сложно для отладки.
- **Исправление:** Рассмотреть `StateFlow` для состояния координатора вместо мутабельных свойств.

## 🟢 НИЗКИЕ (Code Quality / Style)

### 8. `HandwritingTraining` — `history` как `ArrayDeque<PracticeCell>` без лимита

- **Файл:** `domain/practice/src/main/kotlin/ru/mobui/kanji/domain/practice/HandwritingTraining.kt:39`
- **Проблема:** `history` — это `Map<String, ArrayDeque<PracticeCell>>`. Каждый `edit()` добавляет предыдущую ячейку в очередь. Нет лимита истории — при длительной работе над заданием память растёт.
- **Исправление:** Добавить лимит на размер deque (например, 50 записей на кандзи). При переполнении удалять самые старые.

### 9. `CatalogBrowseViewModel` — `MutableStateFlow` для `search` дублирует состояние

- **Файл:** `feature/catalog/src/main/kotlin/ru/mobui/kanji/feature/catalog/browse/CatalogBrowseViewModel.kt:47`
- **Проблема:** `mutableSearch` дублирует состояние `activeSearch().state`. При `query()` или `toggleSearch()` нужно обновлять оба. Риск рассинхронизации.
- **Исправление:** Убрать `mutableSearch` и использовать `activeSearch().state` напрямую.

### 10. `KanjiWritingPad` — `PadPaths` пересоздаются при каждом рекомпозиции

- **Файл:** `core/writingpad/src/main/kotlin/ru/mobui/kanji/core/writingpad/KanjiWritingPad.kt:76`
- **Проблема:** `rememberPadPaths()` зависит от `state.content, canvasSize, inset`. Если `state.content` меняется (новая stroke), все пути перестраиваются. Для сложных кандзи (20+ штрихов) это может быть заметно.
- **Исправление:** Кэшировать `Path` по stroke ID, перестраивать только изменённые.

### 11. `RecognitionSettings` — 20+ параметров в одной data class

- **Файл:** `domain/practice/src/main/kotlin/ru/mobui/kanji/domain/practice/RecognitionSettings.kt:10`
- **Проблема:** 20+ свойств — это «божественный объект». `roundedParameters()` содержит логику округления + валидации + `compensationsFromLimits()`.
- **Исправление:** Разделить на `ValidationRules` и `UserFacingSettings`. Вынести `roundedParameters()` в отдельный объект-хелпер.

### 12. `CatalogDatabase` — триггеры и индексы в Callback дублируются

- **Файл:** `data/catalogdb/src/main/kotlin/ru/mobui/kanji/data/catalog/CatalogDatabase.kt:29`
- **Проблема:** SQL-триггеры `check_words_origin_*` создаются в `onCreate`. Индексы `source_words_*` создаются и в `onCreate`, и в `onOpen` (с `IF NOT EXISTS`). Дублирование — не ошибка, но запутанно.
- **Исправление:** Объединить в `onCreate`, использовать `IF NOT EXISTS` везде.
