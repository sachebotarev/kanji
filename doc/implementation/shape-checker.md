# Локальная проверка формы кандзи

**Текущее состояние:** по умолчанию используется исправленный [Procrustes](procrustes.md), профиль смартфона 72% / 4.8% / бюджет 28%. Описанная ниже последовательность стадий и прежняя калибровка относятся к Cascade, если явно не указано иное. Оба варианта доступны через `pipelineType`; исходные проверки количества черт, крючков и словаря общие.

Согласованные продуктовые правила: [единый документ договорённостей](../decisions/handwriting-verification.md). Экран регулировки: [настройки проверки](../screens/checker-settings.md). Аудит и калибровка: [отчёт](../reviews/shape-checker-2026-10-19.md).

## Границы и порядок

`:checker:shape` — Kotlin/JVM за доменным `KanjiChecker`, независимо от Android, Compose и KanjiVG. `ShapeKanjiChecker` получает эталон через `KanjiReferenceSource`, выполняет вычисления в переданном dispatcher и возвращает `CheckReport`. Публичный вызов `ShapeMatcher(config).compare(...)` сохранён; внутренние этапы и рабочие координаты — `internal`. Зависимости передаются через конструкторы.

`ShapeCompensationPipeline` полностью подготавливает геометрию до проверки:

**сдвиг → перекос (shear) → единый размер → растяжение X/Y → вращение → дрожание → хвосты → сравнение.**

Каждый этап получает результат предыдущего. Компенсации не вызывают проверку. Результат включает геометрию, фактические поправки и ошибки пределов; ошибки не стираются последующими преобразованиями. Исходный `WritingSample`, время, история и число штрихов не изменяются. Рабочий `ShapePoint` допускает выход за пределы 0…1.

## Компенсации

- `TranslationCompensator`: совмещает левый верхний угол ограничивающего прямоугольника ввода с эталоном. `dx = reference.left − input.left`, аналогично Y. Поправки в процентах ширины/высоты поля: `100 × dx/dy`; плюс означает вправо/вниз. Превышение по любой оси — `TranslationCompensation.hasError`. Измеряется исходная геометрия до остальных преобразований.
- `ShearCompensator`: оценивает разницу наклона близких к вертикали участков ввода и эталона по длинным почти прямым чертам, близким к вертикали, через взвешенную медиану; выполняет горизонтальный shear с сохранением выровненного левого края. Угол ограничивается отдельно, перемещение входит в бюджет. При недостатке вертикальных участков коррекция не выполняется. Это эвристика, не оценка наклона на любом знаке.
- `SizeCompensator`: единый коэффициент `reference.longestSide / input.longestSide`, масштабирование относительно уже выровненного левого верхнего угла. Пропорции сохраняются. `changePercent = (factor − 1) × 100`: плюс — растяжение, минус — сжатие. Предел проверяется по модулю; нулевой размер считается неопределимой компенсацией и ошибкой. Одним фактором нельзя совместить одновременно обе стороны при разных пропорциях.
- `StretchCompensator`: после общего размера отдельно подгоняет ширину и высоту к эталону, сохраняя левый верхний угол. Возвращает коэффициенты, проценты по каждой оси и ошибку превышения любого из двух пределов. Если сторона нулевая у обоих рисунков, её коэффициент равен 1; нулевая только у одного — ошибка. Прежний `ProportionCompensator` с ограниченной сеткой множителей заменён этим этапом.
- `RotationCompensator`: готовит повороты вокруг центра и четырёх углов ограничивающего прямоугольника. Возвращает угол, точку вращения и превышение разрешённого угла. Поиск идёт до ±45° с шагом 1°, дополнительно включены точные ±предел и ±половина предела. Углы за разрешённым пределом нужны для диагностики чрезмерной коррекции, но не могут дать принятый ответ. Ноль разрешает принять только вариант без поворота; поиск для диагностики сохраняется. Положительный угол в экранных координатах — по часовой стрелке. Оценённая поправка относится к выбранному варианту, не является гарантированным измерением физического наклона почерка.
- `JitterCompensator`: итеративное упрощение Ramer–Douglas–Peucker с ограниченным расстоянием исходных точек до сохранённых сегментов. Сохраняет оба конца и число штрихов, не зависит от количества повторённых точек. Возвращает число исключённых точек и максимальное отклонение. Ноль отключает обработку. Не является классификатором дрожания: изгиб в пределах допуска тоже может быть упрощён; большие колебания остаются для сравнения.
- `StrokeEndpointCompensator`: после вращения и дрожания готовит дополнительный вариант с удалёнными короткими резкими хвостами. Обрабатывает оба конца; отклонение от устойчивого предшествующего направления минимум 75°. Длина одного хвоста ограничена долей большей стороны, суммарно сохраняется минимум 88% длины каждого штриха. Возвращает число концов и процент исключённой суммарной длины. Вариант без удаления сохраняется, чтобы не стирать настоящий крючок безусловно. Длинные хвосты остаются в геометрии; сам этап не превышает заданный предел.

Для вращения максимум 451 вариант, с хвостами — до 902. Все варианты готовятся до вычисления оценок. Число фактически оценённых вариантов возвращается отдельно. Это увеличивает расходы подготовки и памяти; оптимизацию следует делать по профилю, сохраняя разделение этапов.

## Жёсткие пределы и накопительный бюджет

Проверяются независимо:

1. Точное число штрихов. Порядок и направление игнорируются. Меньшее количество — `Incomplete`, большее — `Incorrect`.
2. Пределы отдельных компенсаций. Все обнаруженные нарушения возвращаются в `CheckCompensation.failures`, затем в `CheckReport.failures`.
3. Общий бюджет `CompensationBudget`.
4. Минимальное двустороннее покрытие формы.

Для бюджета нельзя складывать проценты размеров, градусы и доли длины штрихов напрямую. Используется единая геометрическая мера. Для сдвига, shear, масштаба, растяжения и вращения стоимость этапа — максимальное перемещение соответствующей точки, делённое на **большую сторону исходного эталона**, умноженное на 100. Для сглаживания и хвостов — максимальное расстояние исходной точки до оставшейся ломаной **того же штриха**, в тех же единицах. Максимум не зависит от скорости записи точек. Все семь неотрицательных стоимостей суммируются: противоположные изменения не отменяют расход.

`totalPercent > limitPercent` даёт отдельный `CheckFailure.Budget`, даже когда все индивидуальные пределы и форма прошли. Равенство допускается; малый численный запас применяется только для округления Float на границе. Эта шкала означает суммарное геометрическое вмешательство, не вероятность ошибки и не буквальную сумму процентов из настроек. Пример: 4 единицы сдвига + 3 масштаба + 4 вращения = 11, при бюджете 10 знак отклоняется.

При выборе вариантов сначала предпочитается вариант, проходящий **все** условия принятия, затем большее покрытие, при равенстве — меньший бюджет. Поэтому сильная запрещённая коррекция не вытесняет допустимое совпадение. Полные 100% завершают оценивание только при отсутствии ошибок компенсаций. Если ни один вариант не проходит, возвращается наиболее близкий вариант с причинами отказа.

## Итоговое сравнение

`RasterShapeChecker` получает готовые варианты и эталон. Он использует общий квадратный viewport для эталона и текущего варианта, растеризует в 128×128 и вычисляет двупроходное поле расстояний. Каждый рисунок **не** нормализуется независимо: скрытого выравнивания/масштабирования после компенсаций больше нет. Иначе различие вращения вокруг центра и углов исчезло бы.

Допуск расстояния привязан к большей стороне эталона, а не к расширенному viewport; посторонние кандидаты не меняют оценку текущей пары. Считаются покрытие ввода эталоном и покрытие эталона вводом; итог — минимум. Повторное проведение одной линии не увеличивает её вес. Нулевой рисунок получает 0. Итоговый процент — покрытие, не вероятность правильности. Увеличенный viewport может снижать пространственное разрешение сетки; это известное ограничение растрового метода.

## Диагностика и красный слой

`CheckReport` содержит вердикт, все причины отказа, `CheckCompensation` с результатом каждого этапа и бюджетом, а в debug — расширенные метрики и `compensatedDrawing`. Последнее — неизменяемый снимок **выбранной геометрии, реально использованной для сравнения**, включая варианты, отклонённые из-за пределов/бюджета. `ComparisonPoint` допускает конечные координаты вне 0…1; пользовательские точки остаются нормализованными.

В debug рядом с подсказкой есть переключатель красного слоя. Он доступен после получения актуального рисунка от анализатора. `KanjiWritingPad` только отображает переданный слой красным поверх ввода, без повторного выравнивания, с обрезкой по полю; он не вызывает анализатор и не меняет историю. Слой скрывается при новом жесте, редактировании, выборе другой позиции и завершении задания. Release скрывает кнопку и не получает геометрию диагностики. Для неполного рисунка в debug вычисляется геометрия, но вердикт остаётся `Incomplete`.

Расширенные метрики и причины показываются в [окне отладки](debug-inspector.md), привязаны к позиции и ревизии. Существующая отмена проверки сохраняется.

## Проверки и ограничения

JVM-тесты покрывают пределы сдвига, размера, растяжения, вращение вокруг всех пяти точек, общий viewport, ограничение дрожания, хвосты, сохранность ввода, отдельные и суммарные ошибки. Отдельный Compose-тест проверяет кнопку, красные пиксели на холсте и сброс слоя при новом жесте.

Геометрическая проверка не измеряет каллиграфию и не гарантирует различение всех похожих кандзи. Начальные bounding boxes чувствительны к выбросам; порядок преобразований влияет на измеренные поправки. Размер и отдельные растяжения связаны. Исследования распознавания жестов и сопоставления форм поддерживают идею ограниченных преобразований и штрафа за вмешательство, но не доказывают оптимальность этой конкретной цепочки или бюджета 10% для кандзи.

Источники принципов: [Shape Contexts](https://people.eecs.berkeley.edu/~malik/papers/BMP-shape.pdf) — ошибка сопоставления вместе со стоимостью преобразования; [Coherent Point Drift](https://arxiv.org/abs/0905.2635) — ограничение деформаций через регуляризацию; [$P](https://depts.washington.edu/acelab/proj/dollar/pdollar.html) — сопоставление жестов как облаков точек, а не готовая система оценки правильности кандзи.

## Полностью автономные эталоны

В `data/kanjivg/src/main/assets/kanjivg/` включены **6 984 базовых SVG** из [KanjiVG](https://github.com/KanjiVG/kanjivg/tree/master/kanji), полученных 2026-10-19. Именованные варианты не включены. Это весь базовый набор источника, а не все существующие знаки Unicode. Манифест контрольных сумм сохранён в `doc/implementation/kanjivg-assets.sha256`.

Сборка и приложение используют файлы из исходников: загрузчиков, сетевого API, фоновой докачки и зависимости от доступности сервера нет. Разрешение INTERNET в приложении отсутствует. Неизвестный идентификатор возвращает `Unavailable`, а не неправильный ответ и не инициирует сетевой запрос.

Источник поддерживает ключи `u` + Unicode hex, например `u6771` → `06771.svg`. Эта договорённость локализована в адаптере KanjiVG; домен и геометрический анализатор её не знают. Адаптер нормализует StrokePaths в нейтральные ломаные и отдельно читает StrokeNumbers для подписей подсказки. Номера не участвуют в геометрическом сравнении. Оригинальные SVG и сведения об авторстве сохранены, лицензия CC BY-SA 3.0, полный текст `COPYING` находится рядом с assets. Нормализованные эталоны — производные от этих иллюстраций.


## Словарные особенности, порядок и направление

Смысловые связи хранятся адресно в `KanjiRuleDictionary`, за доменным `KanjiRulesSource`. Формат — **черта A → отношение → черта B**, необязательный допуск. Стартовый набор минимален: по одной записи для 牛, 午, 未, 末, 土, 士. [Полная таблица и порядок ведения](kanji-rule-dictionary.md).

`StrokeChecks` работает по исходному рисунку до компенсаций. `StrokeCorrespondence` нормализует копии исключительно для взаимно однозначного сопоставления черт по симметричному геометрическому расстоянию (венгерский алгоритм); эти рабочие копии не подменяют геометрию итогового сравнения и не являются новой компенсацией ввода.

`DictionaryRuleEvaluator` исполняет общие отношения пересечения/окончания и относительной длины. Никакие универсальные правила всех пересечений не назначаются автоматически всем кандзи. У неизвестного словарю знака нет дополнительных адресных ограничений. Несовместимое число черт правила и эталона — `Unavailable`, а не неправильный ответ.

`checkStrokeStructure` включает словарь, по умолчанию true. `connectionTolerancePercent` по умолчанию 5%, `protrusionTolerancePercent` — 3%, `lengthDifferenceTolerancePercent` — 5%. Собственный допуск записи заменяет общий для соответствующего отношения. Ошибки возвращаются как `CheckFailure.KanjiRules` независимо от удаления хвостов/дрожания, процента и бюджета.

`checkStrokeOrder` и `checkStrokeDirection` — отдельные опциональные правила, по умолчанию false. Направление сопоставленных черт сравнивается в прямом и обратном обходе по положениям на длине линии; перестановка черт не отключает проверку направления. Причины возвращаются как `StrokeOrder`, `StrokeDirection`.

## Живые настройки

`RecognitionSettings` принадлежит domain, `ShapeCheckConfig` сохранён как typealias. UI получает общий контракт; `enabledCompensations` переключает каждый из семи этапов. Индивидуальные пределы и общий бюджет можно регулировать независимо. `ShapeKanjiChecker.configProvider` читает один снимок на запрос. `PracticeSession.invalidateChecks()` повышает ревизии непустых пользовательских ячеек и сбрасывает вердикты без изменения черт; ViewModel отменяет старые запросы и кэш.

`CheckerSettingsScreen` доступен из верхней панели тренировки и показывает текущую проверку. Состояние хранится host-ом в `SavedStateHandle`; долговременное хранилище перед продуктивным внедрением пока не добавлено. Подробности — [спецификация экрана](../screens/checker-settings.md).

## Безопасность обязательных крючков

`ReferenceDrawing.hookRequirements` хранит нейтральный признак по каждой черте: Unknown, Required, NotRequired, Optional. Загрузчик KanjiVG переводит известные CJK-типы в этот признак, поддерживает HTTP и HTTPS URI пространства имён, альтернативы через `/` и известные суффиксы a/b/c/v. Неизвестные значения сохраняют Unknown; отсутствие данных не означает отсутствие крючка. В смешанной альтернативе признак Optional, обязательность — только если все варианты содержат крючок. Ручной словарь не разрастается.

`HookChecker` получает исходные черты после сопоставления, до компенсаций. Проверка обязательна независимо от переключателей словаря, порядка и направления. Пропущенный крючок даёт `CheckFailure.MissingHooks` с однобазными номерами эталонных черт; метрики — `hooks.required` и `hooks.missing`. Низкий порог общего покрытия не отменяет эту ошибку.

Начальная геометрическая эвристика сравнивает терминальный поворот и относительный боковой выход с эталоном по длине дуги. Ищет якорь в последних 40% черты с шагом 2%, направление перед якорем измеряет на 15% длины; минимальный поворот 20°, боковой выход 0.5% длины. Допуск направления относительно эталона 60°, величина выхода 35–250% эталонной. Проверяются оба направления ввода, а опциональная проверка направления отдельно запрещает обратное письмо. Это инженерные допуски, требующие калибровки на реальных почерках, не универсальный стандарт. Если тип указывает крючок, но SVG не даёт отчётливого терминального поворота, сравнивается фактический профиль последних 40% черты: точки с шагом 5% длины дуги в локальной системе предшествующего направления, максимальное отклонение 2% длины черты. Проверка не требует дорисовывать отсутствующую в эталоне деталь. Такие номера отдельно попадают в `hooks.referenceAmbiguous`; для них нельзя обещать независимую семантическую проверку крючка, отсутствующего в геометрии источника. Защита очистки сохраняется.

Сопоставленная черта с Required целиком защищена от `JitterCompensator` и `StrokeEndpointCompensator`; пространственные преобразования сохраняют её точки. Если сопоставить черты нельзя, очистка защищает все черты. Остальные черты очищаются как прежде. Хвосты по умолчанию остаются выключены до калибровки.


Проверка совместимости источника: полный первоначальный прогон 6984 SVG обработал 5472 черты с обязательным типом и выявил 171 ложное отклонение из-за пологих/невыраженных окончаний. После уточнения минимального поворота и сравнения профиля все ранее отвергнутые образцы прошли отдельный регрессионный тест. Полный первоначальный прогон не объявляется успешной оценкой финальной эвристики. Отдельные тесты проверяют все десять семейств типов, пропущенный крючок 小, обратное письмо, масштаб, мелкий шум и защиту очистки. Точность на почерках людей ещё не измерена.


## Выбор минимально необходимой компенсации

После жалобы на точную обводку сохранены снимки Pixel: [рисунок](../design/compensation-pixel-current.png) и [отладка](../design/compensation-pixel-debug.png). На них 86% совпадения и расход бюджета 17.98% при лимите 15%; были последовательно применены сдвиг, перекос, размер, растяжение и поворот. Это не доказывает, что все эти поправки нужны.

Теперь исходный рисунок — полноценный кандидат с нулевым бюджетом. Если его геометрия уже проходит заданный порог, дальнейшие геометрические поправки не выполняются; независимые исходные проверки крючков, словаря, порядка и направления остаются обязательными. При несовпадении количества черт возвращается исходная геометрия для отладки, без растягивания незаконченной части до размеров полного знака.

В дополнение к полной цепочке рассматриваются её промежуточные результаты: только сдвиг; сдвиг с перекосом; затем общий размер. Пропущенные последующие стадии соответствуют тождественному преобразованию. Порядок стадий не меняется. Среди проходящих вариантов выбирается меньший фактический расход бюджета, затем большее покрытие; варианты оцениваются по возрастанию расхода. Если ни один не принят, выбирается лучшее покрытие, а при равенстве — меньший бюджет. Исходный вариант остаётся запасным: итоговое покрытие не может стать хуже исходного.

`coverage.baseline.percent` теперь означает реальное покрытие исходного ввода до любых компенсаций. `coverage.gain.percent` — разница итогового и исходного покрытия в процентных пунктах. Бюджет остаётся суммой фактических перемещений по стадиям выбранного варианта: поправки не взаимозачитываются. Индивидуальные ограничения проверяются для фактически применённых стадий. Например, намеренно слишком широкий геометрический допуск может принять рисунок без исправлений; пределы компенсаций не заменяют адекватный допуск сходства.

Порог 95%, расстояние 3.5% и бюджет 15% стартового профиля в этом исправлении не повышались и не снижались. Старые тесты бюджетов, требовавшие исправления даже уже проходящего рисунка, переведены на точное геометрическое условие (99.9%, расстояние 0.2%), чтобы проверять именно предел необходимой компенсации.


## Сходство по сопоставленным чертам

Общий силуэт теряет принадлежность участков отдельным чертам: одинаковое число случайных линий может дать заметное покрытие за счёт пересечений. Поэтому итоговый процент теперь определяется `StrokeShapeChecker`, а прежняя растровая метрика остаётся только диагностической (`coverage.global.percent`).

После взаимно однозначного сопоставления каждая введённая черта сравнивается только со своей эталонной. В обе стороны берутся 49 точек, равномерно расположенных по длине дуги; для точки ищется расстояние до полилинии соответствующей черты. Допуск остаётся долей большей стороны полного эталона и не увеличивается для коротких черт. Проценты усредняются с равным весом черт отдельно для ввода и эталона; итог — минимум двух средних. Нулевая длина обрабатывается как одна точка. Неравное количество черт не даёт сопоставленного процента и по-прежнему блокирует принятие. Частота событий пера не меняет оценку. Порядок и направление проверяются отдельно и остаются опциональными.

`coverage.strokes.percent` показывает новый итог по чертам, `coverage.global.percent` — прежнее общее покрытие. Ни один из процентов не является вероятностью правильного ответа. Все решения о выгоде компенсации и пороге применяются к новой метрике. Эти изменения требуют новой калибровки на человеческих рисунках; старый синтетический отчёт не описывает текущий алгоритм.
