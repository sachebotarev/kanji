# Архитектура и реализация каталога

Документ описывает структуру каталога, правила загрузки поставляемого контента и схему локального хранения.

## Модульная структура

Каталог разделён по уровням Clean Architecture:

- **`:domain:catalog`** (Kotlin/JVM)  
  Не зависит от Android SDK и Room. Содержит модели данных (`Kanji`, `Radical`, `Word`, `Source`), устойчивые идентификаторы, снимок справочника (`CatalogSnapshot`), контракт `CatalogRepository`, а также логику многоязычного поиска и фасетной фильтрации (по чертам, JLPT, ключам и учебникам).
- **`:data:catalogdb`** (Android / Room)  
  Реализует хранение в SQLite через Room (`kanji.db`, версия схемы 12). Отвечает за транзакционную загрузку контента из поставляемых assets, валидацию целостности пакета и триггеры целостности данных. Публичный класс `RoomCatalogRepository` работает на `Dispatchers.IO` и предоставляет потокобезопасный доступ к снимку каталога и личному словарю. До выпуска обновление схемы уничтожает файл базы и ставит её заново.
- **`:feature:catalog`** (Android / Jetpack Compose)  
  Пользовательский интерфейс: дерево экранов учебников, глав, списков кандзи, ключей и слов. Использует `Navigation Compose` с типизированными маршрутами, `StateFlow` и сборку состояния с учётом жизненного цикла (`collectAsStateWithLifecycle`). Тяжёлые операции поиска и фильтрации выполняются в фоновом пуле диспетчера.
- **`:app`**  
  Собирает граф зависимостей вручную и связывает репозиторий с навигацией.

## Загрузка и обновление контента

Приложение поставляется со встроенным учебным пакетом в `assets/seed/` (`manifest.json` и `catalog.json`).

### Алгоритм импорта

1. **Проверка манифеста:** валидация SHA-256 хеша и размера `catalog.json`, сверка версии формата пакета и схемы базы данных.
2. **Проверка установленной версии:** таблица `catalog_installation` хранит хеш текущего установленного пакета. Если хеш совпадает, импорт пропускается. Откат на меньшую версию или несовпадающий хеш без изменения версии отклоняются.
3. **Единая транзакция:**
   - Обновление справочников (ключи, кандзи, слова, учебники и их переводы) через аннотации `@Upsert`.
   - Переустановка связей кандзи с чтениями и источников с учебными материалами.
   - Запись обновлённого хеша в `catalog_installation`.
   - При любой ошибке (нарушение внешних ключей, сбой ввода-вывода) транзакция полностью откатывается.

### Защита личных данных

- **Пространство идентификаторов:** положительные ID принадлежат поставляемому каталогу; отрицательные ID зарезервированы за пользовательскими словами и источниками. Конфликт ключей исключён на уровне соглашения.
- **Неизменяемость происхождения:** триггеры SQLite `check_words_origin_*` и `preserve_words_origin` гарантируют корректность и неизменяемость флага `is_user_created`.
- Поставляемые обновления не удаляют личные слова, пользовательские переводы и архивные записи.

## Схема базы данных (Room 12)

Текущая схема — `kanji.db` версии 12. Экспорт Room 11 остаётся в истории схемы и не является поддерживаемой миграцией. До выпуска `fallbackToDestructiveMigration` заменяет несовместимую базу целиком: каталог ставится из seed заново, личные слова, рецепты и тренировки не сохраняются.

Схема создаётся при чистой установке:

- **Поддержка многоязычности:** таблицы переводов именованы с суффиксом `_translations` (`kanji_translations`, `words_translations`, `radicals_translations`, `sources_translations`) с регистронезависимым тегом языка `language_tag`.
- **Контекстные примечания:** таблица `words_translations` включает поле `usage_note` для подсказок по употреблению слов и предложений.
- **Описания источников:** таблица `sources_translations` включает поле `description` для подробной информации об учебниках и курсах.
- **Целостность и триггеры:** дополнительные ограничения CHECK и частичные уникальные индексы (например, для связей `source_words` с опциональным `kanji_id`) создаются через callback при инициализации БД и файл `catalog-checks.sql`.

Экспорт схемы Room сохраняется в директории `data/catalogdb/schemas/`.

## Поиск и фасетная фильтрация

Логика поиска и фильтрации инкапсулирована в `:domain:catalog`:

- **Фасеты:** списки фильтров по количеству черт, уровням JLPT и ключам рассчитываются динамически. Каждый фасет не исключает результаты собственного фильтра, позволяя пользователю видеть доступное число вариантов при смене значения.
- **Многоязычный поиск:** поиск ищет совпадения по японскому написанию (кандзи, кана), чтению и переводам на активном языке с автоматическим fallback на русский язык.
- **Производительность:** списки в Compose построены на `LazyColumn` и `LazyVerticalGrid`. Фильтрация выполняется на переданном диспетчере без блокировки UI-потока.

## Состояние экранов и актуальность снимка

- Каждая вкладка учебника хранит собственный запрос и фильтры в `SavedStateHandle`. Вычисление списка выбирает запрос из состояния именно текущей вкладки, а не из отдельной изменяемой копии активного поиска.
- Ключ ViewModel зависит от назначения экрана, но не от языка. Изменение языка пересчитывает содержимое на фоновом диспетчере, сохраняя маршрут, запросы и фильтры. Правила русского fallback остаются в domain.
- После успешного `saveWord` или `deleteWord` `RoomCatalogRepository` под тем же mutex сбрасывает кэш и увеличивает наблюдаемую `revision`. Неуспешная транзакция ревизию не меняет. Это локальный счётчик изменений процесса, не версия поставляемого каталога и не версия схемы БД.
- `:app` передаёт текущую ревизию в `CatalogRoute`, включая каталог, открытый из словаря. Владельцы состояния перечитывают снимок при смене ревизии, не сбрасывая пользовательский ввод. Изменение контекста отменяет предыдущий расчёт через `collectLatest`; завершение устаревшего расчёта не публикуется.
- Контракт `CatalogRepository` в domain остаётся независимым от Android и coroutine Flow; реактивная связь data → app → presentation не создаёт зависимости между feature-модулями.
