# Реализация каталога и загрузка содержимого

20 октября 2026 года.

## Границы

- `:domain:catalog` — чистый Kotlin/JVM: устойчивые ID, снимок справочника, контракт `CatalogRepository`, правила локализации/поиска/фильтров и устранения повторов слов.
- `:data:catalogdb` — Room, внутренние entities/DAO, проверка пакета и транзакционное первоначальное заполнение/обновление. `RoomCatalogRepository` получает application Context и IO dispatcher через конструктор. В публичном API нет операций записи.
- `:feature:catalog` — независимые Compose-компоненты, ViewModel с SavedStateHandle, StateFlow и lifecycle-aware сбором. Navigation Compose с сериализуемыми типизированными маршрутами. Содержимое читается в IO, списки фильтруются на переданном computation dispatcher; отмена не преобразуется в ошибку. Полный каталог не сериализуется в состояние Activity.
- `:app` — application lifetime граф вручную связывает репозиторий и маршрут. У dashboard только callback входа, зависимости feature → feature нет.

Добавлены стабильные Room 2.8.5, KSP 2.3.9, Navigation Compose 2.10.2 и Kotlin Serialization 1.9.0; версии централизованы. Существующий Kotlin/AGP не обновлялся. Основа выбора: [Room](https://developer.android.com/jetpack/androidx/releases/room), [Navigation](https://developer.android.com/jetpack/androidx/releases/navigation), [KSP](https://github.com/google/ksp/releases/tag/2.3.9). Принятый механизм Navigation применяется к новому вложенному графу каталога; прежние маршруты главной/практики/настроек не переписаны побочно.

## Загрузка и хранение

Room создаёт `learning.db`. Загрузчик читает `seed/manifest.json` и `seed/catalog.json` из assets, проверяет SHA-256 и размер JSON, версии формата/схемы/наполнения и ожидаемые колонки. Не копирует подготовленный SQLite-файл поверх пользовательской базы.

В одной Room-транзакции:

1. Проверяет текущую версию и хеш; повтор той же версии — без записи, изменение хеша без повышения версии и откат версии отклоняются.
2. Проверяет сохранение ранее опубликованных ID слов и кандзи. Изменение написания/чтения существующего word ID отклоняется до отдельной миграции; источник исключается архивированием, не исчезновением из пакета.
3. Удаляет только заменяемые учебные связи поставляемых источников, затем их места изучения. Вставляет/обновляет по первичным ключам справочники и содержимое, затем связи.
4. Переустанавливает чтения кандзи и группы значений, чтобы удалённые позиции не оставались после обновления. Архивные слова, личные источники/слова/связи и сторонние таблицы не очищаются.
5. Записывает хеш установки и metadata в конце той же транзакции. Ошибка внешнего ключа или отмена откатывает весь импорт.

Добавлена внутренняя таблица `catalog_installation(id, payloadHash)` для обнаружения изменения содержимого без повышения версии. Пользовательские отрицательные ID не пересекаются с положительным реестром каталога. Деструктивного fallback и `INSERT OR REPLACE` нет: Room `@Upsert` обновляет существующую строку, сохраняя ссылки.

Room entities определяют внешние ключи, уникальность, NOCASE языковых тегов и индексы; экспорт схемы хранится в `data/catalogdb/schemas/`. Ограничения CHECK из исходной SQL-схемы поддержаны INSERT/UPDATE-триггерами `data/catalogdb/src/main/assets/catalog-checks.sql`, поскольку аннотации Room не описывают CHECK. Частичные уникальные индексы для nullable `source_words.kanji_id` устанавливаются Room callback при создании БД. Схема создаётся при чистой установке; миграции не регистрируются. Добавлен индекс отдельного `source_kanji.kanji_id` для внешнего ключа.

## Текущие границы

CatalogRepository предоставляет read-only снимок каталога, кэшируемый в application repository. Личный словарь использует отдельный PersonalDictionaryRepository с Room Flow и транзакционными операциями, реализованный тем же адаптером. Room-схема — 3, схема пакета наполнения — 1: это разные контракты. Владение словами описано в [личном словаре](personal-dictionary.md).

Списки ленивые, фильтрация выполняется вне UI-потока, фасеты вычисляет domain. При значительном росте каталога следует отдельно оценить запросы и постраничную загрузку. Развитие личного словаря уже не является отложенной задачей; полноценная статистика занятий остаётся отдельной областью.

Сохраняются переводы языков, не поставленных пакетом, и старые переводы архивных слов. Удаление переводов, объединение дублей, смена идентичности и синхронизация требуют явной политики владения/миграций, а не молчаливого переноса статистики. Установщик не заменяет ручные записи и не меняет их происхождение.

[Подготовка пакета](../imports/catalog/README.md). UI, фильтры и экранные вопросы описаны в [модуле каталога](../design-system/05-screens/catalog/README.md).

## Нативный каталог

Схема 3 рассчитана на чистую установку приложения. Поддержка обновления старых установок и миграция 1 → 2 удалены. Дополнения `data/catalog/content` загружаются транзакционно вместе с seed: школьная ступень/год, уровень JLPT, перевод с примечанием и описание учебника. Хеш установки включает дополнения. Идентичность, чтения и учебные связи сохраняются.

Доменные фильтры черт и JLPT пересекаются с главой и ключом; фасеты игнорируют собственное условие. Неизвестный уровень выделен типом `Missing`. Язык примечания определяется строкой перевода. `CatalogTheme` ограничивает палитру разделом каталога; остальные feature-модули не меняются. `KanjiTile`, `CatalogFilterChip`, `NumericFilterScreen`, `CatalogStatus` и `KanjiDrawing` принимают состояние и события без DI. Загрузчик KanjiVG передаётся из app в ViewModel через конструктор.

Поиск открывается отдельно и при закрытии очищает только запрос. Вкладки сохраняют свои запросы, открытость поиска, главу и состояние lazy-списков. Заголовок и вкладки закреплены, прокручивается панель поиска/фильтров.
