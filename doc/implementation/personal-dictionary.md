# Личный словарь: хранение и общие компоненты

21 октября 2026 года. Основа: [экраны](../screens/personal-dictionary.md), [общая модель слов](../database/words.md).

## Границы

- `:domain:catalog`: `CatalogWord.isUserCreated`, `WordDraft`, переводы с языковыми тегами, валидация и `PersonalDictionaryRepository`. Чистый Kotlin/JVM; Flow — контракт наблюдения. Пустые написание/чтение, пустые переводы, некорректные BCP 47 теги и повторные канонические языки (включая алиасы) отклоняются. Подготовка не меняет японское написание или форму выражения, только убирает крайние пробелы.
- `:data:catalogdb`: один `RoomCatalogRepository` реализует раздельные контракты чтения каталога и операций личного словаря. Каталог остаётся read-only API. Room-наблюдение учитывает изменения слов, переводов, частей чтения и личных связей. Инициализация завершается до наблюдения, операции выполняются в IO и транзакциях. Репозиторий сериализует запись и построение снимков mutex; после успешной записи кэш каталога сбрасывается. Снимок справочных кандзи в открытом разделе не содержит пользовательского состояния формы.
- `:core:wordui`: общие строки/списки, поиск, информационные панели, секции, строки переходов, содержимое карточки и форма редактора. Виджеты получают состояние, Modifier и callbacks, без ViewModel, DI, репозитория и самостоятельной навигации. Форма используется при создании и изменении, карточка — в каталоге и личном словаре.
- `:feature:dictionary`: наблюдаемое состояние списка и операций, SavedStateHandle редактора и типизированная вложенная Navigation Compose. Поиск вычисляется на переданном computation dispatcher. Результаты записи хранятся в состоянии; корутины сохраняют отмену. Прямой зависимости от `:feature:catalog` нет: приложение передаёт composable для существующих справочных маршрутов.
- `:app`: один экземпляр хранилища в application graph, переход с главной и действительный счётчик личных записей через ViewModel. Пока счётчик не получен, показано описание вместо вымышленного числа. Остальная демонстрационная статистика главной не становится статистикой личного словаря.

## Миграция Room 1 → 2

`words.is_user_created INTEGER NOT NULL DEFAULT 0`: происхождение независимо от языка и связей. Новые ручные записи получают 1, записи пакета — 0. Существующие записи сохраняются с 0: прежние данные не доказывают ручного происхождения. Знак ID не используется как разрешение редактирования. SQL-триггеры проверяют 0/1 и запрещают менять происхождение уже существующей записи.

Миграция выполняет ALTER TABLE без пересоздания БД; старые переводы, связи, триггеры и статистика сохраняются. Два частичных уникальных индекса source_words не представлены в Room entities. Room сравнивает их с экспортированной схемой и отклоняет как лишние при миграции: миграция снимает только эти два индекса перед проверкой, `Callback.onOpen` восстанавливает их через CREATE UNIQUE INDEX IF NOT EXISTS до предоставления БД потребителям. После аварийного закрытия между миграцией и onOpen следующий open также восстановит индексы. При новой БД они создаются в onCreate и проверяются в onOpen. Отдельный тест миграции проверяет сохранение данных, уникальности связей с NULL и прежних проверочных триггеров.

Room-схема 2 и схема пакета наполнения 1 — разные контракты. JSON-пакет и SQL начального наполнения сохраняют свой формат: отсутствующий в пакете признак имеет default 0 в адаптере. Версия `catalog_metadata.schema_version` относится к пакету наполнения, не PRAGMA user_version Room.

## Запись и удаление

Создание выделяет отрицательные ID слова, личного источника и связи внутри транзакции. Личный источник определяется типом personal, а не переводным названием. Изменение проверяет существование, отсутствие архива и ручное происхождение, затем меняет независимые поля и набор переводов атомарно. При изменении написания/чтения прежние части чтения удаляются как более не подтверждённые. Остальные языки редактор загружает и сохраняет явно; отсутствие языка в форме после удаления означает удаление строки перевода.

Удаление доступно только ручным словам: архивирование плюс снятие личных связей сохраняет ID и внешние ссылки. Архивная ручная запись может быть восстановлена созданием той же пары; архивная запись каталога ручной не становится. Конфликты с активными записями отклоняются, без перезаписи и автоматической смены происхождения.

Установщик пакета сохраняет личные записи и их переводы. Если будущий пакет пытается занять ID или пару написания/чтения ручного слова, обновление отклоняется до изменений: требуется отдельное явное разрешение конфликта. Установщик не меняет ручной признак на поставляемый.
