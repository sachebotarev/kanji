# Оценка слова по подсказкам кандзи и чтения

Статус: **подключено** к `Training.summarize` / PRACTICE.01. Согласует учёт помощи с режимами подсказки из [hints.md](hints.md) и заменяет плоский балл `assisted = 0.6` из прежней версии [training-grade.md](training-grade.md).

## Зачем

Слово с одной лёгкой подсказкой и слово на грани лимита не должны давать один и тот же балл. Нужна шкала, где:

- каждое **засчитанное** нажатие подсказки по кандзи снижает балл;
- раскрытие **произношения** слова — отдельный штраф;
- просмотр эталона на уже **верном** знаке и выключение подсказки **не** штрафуют.

## Вход на одно задание (слово)

- `H` — лимит подсказок на знак (`RecognitionSettings.maxNextStrokeHints`, по умолчанию 3).
- По каждому символу с `role = practice`:
  - `status` — `correct` / `incorrect` / …;
  - `k` — `hint_request_count` (число **засчитанных** показов; ≥ 0, не уменьшается).
- `reading_hint_used` — было ли раскрыто чтение слова (spoiler), один раз за задание.

Предзаполненные символы (`prefilled`) в средний балл кандзи **не** входят.

Свободный бледный эталон на уже `correct` знаке в `k` **не** входит.

## Балл одного кандзи

```text
если status = incorrect (в т.ч. исчерпание лимита):
    cell = 0
иначе если status = correct:
    cell = max(0, 1 − k / H)
иначе:
    # editing/empty на итоговом слове не ожидаются
    cell = 0
```

Примеры при `H = 3`:

| k | cell |
| --- | --- |
| 0 | 1.00 |
| 1 | 0.67 |
| 2 | 0.33 |
| ≥ H (обычно уже incorrect) | 0 |

Линейная шкала: первая подсказка ещё «дорого» оставляет две трети балла; на последней допустимой подсказке остаётся треть — согласуется с жёлтой/красной лампочкой.

## Балл слова

```text
kanjiAvg = среднее(cell) по practice-символам
           (если practice-символов нет — 1.0)

readingFactor = 0.85, если reading_hint_used = true
                1.00 иначе

wordPoints = kanjiAvg × readingFactor
```

Штраф чтения **15%** от уже посчитанного среднего по знакам: открытие произношения помогает всему слову, но слабее, чем полная сдача одного кандзи.

Примеры (`H = 3`, два practice-знака):

| Подсказки по знакам | Чтение | wordPoints |
| --- | --- | --- |
| 0 + 0 | скрыто | 1.00 |
| 0 + 0 | открыто | 0.85 |
| 1 + 0 | скрыто | 0.83 |
| 1 + 1 | открыто | ≈ 0.57 |
| 2 + 2 | скрыто | 0.33 |
| любой incorrect | любое | 0 (см. ниже) |

## Связь со статусом задания

Терминальный статус для хранения и UI-счётчиков:

| Условие | `TrainingTaskStatus` | `wordPoints` в сумме тренировки |
| --- | --- | --- |
| Все practice `correct`, `k = 0` у всех, чтение не открыто | `correct` | `wordPoints` (= 1.0) |
| Все practice `correct`, но был `k > 0` или открыто чтение | `assisted` | `wordPoints` из формулы |
| Есть practice `incorrect`, либо пользовательский пропуск | `skipped` | **0** |
| Таймаут | `timed_out` | **0.25** |

Итог тренировки:

```text
percent = round(100 × Σ wordPoints / N)
```

Уровни `excellent` / `steady` / `keep_going` — те же пороги 85 / 55, что в [training-grade.md](training-grade.md).

Код: `HintScoring.kt` (`practiceSymbolPoints`, `TrainingTask.wordPoints`), `Training.summarize`. PRACTICE пишет `strokeHintCount` → `hint_request_count` и `readingHintUsed` → `reading_hint_used` при закрытии задания.

## Сознательные ограничения

- Не учитывает «качество» неправильного ввода до исчерпания — только засчитанные подсказки и исход знака.
- Не штрафует повторные просмотры эталона на уже верном знаке.
- Не различает FullCharacter и NextStroke: оба жгут один счётчик `k`.
- Пропуск и таймаут по-прежнему грубые (0 / 0.25), без разбора подсказок внутри оборванного слова.

## Альтернативы (отклонены)

- Экспоненциальный штраф `0.6^k` — слишком жёстко бьёт по одной подсказке.
- Чтение как ещё один «виртуальный кандзи» с весом 1 — слишком сильно относительно одного знака в длинном слове.
- Разный `H` для режимов — усложняет настройку без явной пользы.
