# UI-PAD — реализация Android

Статус: базовый виджет реализован. Экран одного слова реализован отдельно; подключён локальный анализатор общей формы. Основание: [UI-PAD](../components/practice-components.md#writing-pad), [экран](../screens/kanji-practice.md), [архитектура](../architecture.md).

## Размещение

- `:domain:handwriting` — чистый Kotlin/JVM: `InkPoint`, `InkStroke`, `InkTool`, `WritingSample`. Нет зависимостей на Android, Compose или поставщика эталонов.
- `:core:writingpad` — Compose-библиотека: виджет, UI-контракт, semantics, preview и три инструментальных теста.
- `:feature:practice` — внешний владелец состояния поля на экране слова. `:app` запускает демо «Библиотека» и собирает зависимости; см. [контракт экрана](practice-screen.md).

UI-PAD отвечает за отображение и ввод. История, undo, очистка, подсказки, сохранение, распознавание и решение о завершении знака остаются снаружи. Для виджета DI и ViewModel не нужны.

## Вход

```kotlin
@Composable
fun KanjiWritingPad(
    state: PadUiState,
    onEvent: (PadEvent) -> Unit,
    modifier: Modifier = Modifier,
)
```

`PadUiState` содержит:

| Поле | Назначение |
| --- | --- |
| `version: ContentVersion` | Идентификатор ячейки и ревизия содержимого |
| `content: PadContent` | `Empty`, `UserInk(WritingSample)` или `Reference(ReferenceDrawing)` |
| `inputEnabled: Boolean` | Разрешение ввода без скрытия содержимого |
| `overlay: ReferenceDrawing?` | Бледный эталонный фон под пользовательскими штрихами для обводки |

`ReferenceDrawing` и `ReferencePoint` находятся в `:domain:handwriting`; это независимые от источника полилинии с `ReferencePoint(x, y)` в координатах 0…1. Внешний адаптер подготавливает их из любого эталона. Виджет не загружает SVG и не знает ожидаемый кандзи. Эталон не представляется пользовательским ответом; при начале нового жеста временно скрывается, при отмене снова виден. Принятый штрих заменяет эталон во внешнем владельце состояния.

Внешний `Modifier` управляет размещением и размерами, виджет сохраняет квадратную форму. Текущие параметры оформления: MaterialTheme, радиус 16 dp, направляющие, перо 4 dp, внутренний отступ 8 dp. Цвета определяет тема приложения; отдельного публичного `PadStyle` в первой версии нет.

## Выход

| Событие | Назначение |
| --- | --- |
| `StrokeFinished(baseVersion, gestureId, stroke)` | Один завершённый штрих после отпускания указателя |
| `GesturePreview(baseVersion, gestureId, stroke?)` | Временный штрих для миниатюры; `null` очищает превью при завершении или отмене |

Владелец принимает завершение синхронно в UI-потоке, проверяет `baseVersion`, сохраняет историю, создаёт новое содержимое и увеличивает ревизию. Сначала выдаётся завершение, затем очистка превью. Превью не сохраняется и не проверяется. `gestureId` различает жесты в пределах экземпляра виджета; вместе с версией позволяет связать события. Повторные или устаревшие события не должны повторно добавлять штрих.

Ревизия растёт при каждом изменении, в том числе при undo; восстановление рисунка не возвращает старую ревизию. Результат проверки применяется только к совпадающей актуальной версии. Это реализовано внешним владельцем состояния в `:domain:practice` и `:feature:practice`.

## Формат штрихов

`InkPoint(x: Float, y: Float, elapsedMs: Long)` содержит координаты в **квадрате 0…1** и время от начала штриха. Начало сверху слева, X вправо, Y вниз. Координаты конечные, время начинается с нуля и не убывает. `InkStroke` содержит непустой неизменяемый снимок точек и тип указателя. `WritingSample` — снимок завершённых штрихов в порядке написания, в том числе пустой. Конструкторы копируют входные списки.

Порядок точек сохраняет направление движения; отрыв указателя разделяет штрихи. Короткое касание сохраняется и рисуется точкой. В данные не входят толщина пера, рамка, направляющие и цвет. Рисунок не растягивается по собственному bounding box: его расположение относительно поля сохраняется.

```text
x = (xPx - drawingRect.left) / drawingRect.width
y = (yPx - drawingRect.top) / drawingRect.height
```

`drawingRect` — квадрат внутри рамки с отступом 8 dp. Один и тот же перевод координат применяется к пользовательскому вводу и эталону. Изменение размеров не меняет сохранённые данные.

Формат не зависит от KanjiVG. Для этого источника адаптер может нормализовать SVG-координаты 109 × 109 делением на 109 и семплировать кривые. Для другого источника адаптер выполняет собственное преобразование, включая растеризацию для ML-модели при необходимости. Форматы поставщика и его идентификаторы не попадают в UI-контракт. Источник сведений о KanjiVG: [Files](https://kanjivg.tagaini.net/files.html).

## Поведение ввода

- Один активный указатель: палец, стилус или основная кнопка мыши. Дополнительные указатели не создают штрихи; масштабирования и прокрутки внутри поля нет.
- Начало записывается сразу при down, без ожидания touch slop. Принятый жест потребляет события.
- Выход за полезную область, отмена системой, внешняя смена версии, размера или разрешения ввода отменяют активный жест, очищая превью. Завершение в этих случаях не выдаётся.
- Используются текущие точки стабильного pointer API Compose. Исторические точки пакетов и специфичная обработка стилуса пока не включены; экспериментальные API не используются. Качество быстрого ввода стилусом требует проверки на физическом устройстве.
- Отрисовка полилиний с круглыми концами не меняет исходные точки. Завершённые пути кэшируются по содержимому и размеру; текущий путь обновляется в фазе рисования.
- Поле имеет название для диктора, число штрихов или описание показанного образца и признак отключённого ввода. Движения не озвучиваются. Доступность полного рукописного сценария с TalkBack требует отдельного исследования.

Реализация использует Compose `Canvas` и `pointerInput`. Справка: [рисование](https://developer.android.com/develop/ui/compose/graphics/draw/overview), [жесты](https://developer.android.com/develop/ui/compose/touch-input/pointer-input/understand-gestures).

## Минимальные проверки

Три Compose UI-теста в `KanjiWritingPadTest`:

1. Жест выдаёт ровно один завершённый штрих с координатами 0…1, сохранённым направлением и монотонным временем; превью очищается.
2. Отмена не создаёт завершённый штрих и очищает превью.
3. Отключённый ввод не выдаёт событий.

```sh
./gradlew :domain:handwriting:build :core:writingpad:lintDebug :app:assembleDebug
./gradlew :core:writingpad:connectedDebugAndroidTest
```

Вторая команда требует устройства или эмулятора. История и сравнение с эталонами намеренно не тестируются в виджете: они проверяются отдельно в модуле практики.

Проверено 19 октября 2026 года: все три теста прошли на эмуляторе Pixel 4a с Android 15 и устройстве Pixel 10 Pro с Android 17. Сборка приложения и lint модуля проходят. AndroidX Test JUnit обновлён до stable 1.3.0 и Espresso до stable 3.7.0 для совместимости тестовой инфраструктуры с Android 17. После устранения замечания об autoboxing состояния lint не сообщает проблем.

Изначальное изолированное демо поля заменено экраном одного слова. Исторический скриншот изолированного поля удалён; актуальные снимки экрана сохраняются в `doc/design/`.

`ReferenceDrawing.strokeNumbers` — необязательные нейтральные подписи `ReferenceStrokeNumber(number, x, y)`. При включённом `overlay` поле рисует их вместе с фоновым эталоном, под пользовательскими линиями. Координаты подписей — нормализованные базовые линии текста; в отличие от геометрии штрихов, могут лежать за границей viewport источника. При отображении подписи ограничиваются границами поля. Они не становятся входными штрихами.
