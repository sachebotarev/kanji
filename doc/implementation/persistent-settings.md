# Постоянные настройки проверки кандзи

## Хранилище и границы

`RecognitionSettingsRepository` находится в `:domain:practice` и не зависит от Android. `:data:settings` реализует его через Preferences DataStore. Выбрано файловое асинхронное хранилище небольших типизированных параметров, без таблиц и запросов Room. Зависимость `androidx.datastore:datastore-preferences:1.1.7` зафиксирована в каталоге: стабильный выпуск, доступный в локальном кэше и проверенный с текущим toolchain, без побочного обновления остальных библиотек. Официальное описание: [DataStore](https://developer.android.com/topic/libraries/architecture/datastore), [release 1.1.7](https://developer.android.com/jetpack/androidx/releases/datastore#1.1.7).

Файл `files/datastore/recognition_settings.preferences_pb` принадлежит приложению. Один экземпляр DataStore на файл обеспечивается приватным context delegate адаптера. Хранятся все пользовательские параметры и независимые флаги чекеров; nullable-лимиты кодируются NaN, набор компенсаций вычисляется из лимитов. Каждый снимок записывается одной транзакцией edit, с отдельными именованными ключами и версией схемы.

`KanjiApplication` владеет application lifetime scope и репозиторием. MainActivity получает их только в точке сборки и передаёт через конструктор RecognitionSettingsViewModel. Виджеты не обращаются к контейнеру. ViewModel удерживает текущее состояние и последовательно сохраняет снимки под Mutex. Запрошенные записи не отменяются при закрытии Activity. Завершение suspend save означает завершённую запись DataStore; принудительное убийство процесса до завершения ещё выполняющейся операции не является подтверждением сохранения.

Перед отображением экранов приложение ждёт чтения DataStore: значения по умолчанию не используются тренировкой до загрузки. При ошибке чтения или записи показана повторная попытка. Defaults применяются при отсутствии сохранённого файла. «Сбросить» также записывает новый снимок. SavedStateHandle сохранён для миграции ранее восстановленных параметров; существующий DataStore всегда приоритетнее Bundle. Очистка данных/удаление приложения удаляют локальные настройки согласно стандартному жизненному циклу Android.

## Навигация

Шестерёнка на главной → независимый экран настроек `:feature:settings` (`SETTINGS`), на котором сгруппированы пользовательские параметры приложения:
1. **Ход тренировки:** переключатели автоперехода к следующему кандзи (`autoAdvanceKanjiOnSuccess`) и к следующему слову при безошибочном вводе (`autoAdvanceOnSuccess`).
2. **Подсказки:** лимит подсказок следующей черты (`maxNextStrokeHints`) и время показа эталонного знака (`fullHintDisplayMillis`).
3. **Модули проверки:** независимое включение/выключение чекеров (читаемость `readabilityEnabled`, порядок и направление черт `strokeWritingEnabled`, форма знака `shapeEnabled`), а также статус и загрузка японской языковой модели ML Kit.
4. **Калибровка формы кандзи (только в develop/debug сборках):** пункт входа на экран `CheckerSettingsScreen` (`SETTINGS.01`), где настраиваются геометрические допуски совпадения формы, компенсаций трансформаций, бюджета и особенностей структуры черт. В release-сборке карточка калибровки скрыта (`showCalibration = BuildConfig.DEBUG`).
5. **Данные и память:** очистка истории тренировок с подтверждающим диалогом (`TrainingsRepository.clearHistory` на IO-потоке).

Настройки и калибровка проверок `CheckerSettingsScreen` (`SETTINGS.01`) открываются из `SETTINGS`. Параметры общие и сохраняются в DataStore.

## Проверки

- Инструментальный тест data-модуля записывает все параметры, закрывает scope DataStore, открывает файл новым экземпляром и проверяет снимок; затем аналогично проверяет сохранение сброса.
- AppSettingsNavigationTest проверяет путь настроек, пересоздание Activity, обратный переход и общность значений с практикой.
- Существующие тесты восстановления SavedStateHandle сохраняют проверку прежней схемы и округления, используя подставной репозиторий.
