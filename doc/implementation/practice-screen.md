# Экран одного слова: контракт и реализация

Статус: реализован экран одного задания; полноценный цикл сессии ещё не подключён. Дизайн: [SCR-KANJI-PRACTICE](../design-system/05-screens/practice/README.md). Требования: [архитектура](../architecture.md).

Экран отвечает за одно задание, а не за группу слов. Внешний компонент выбирает следующее задание, хранит прогресс группы и принимает результат. Формат файла/базы заданий пока не определён: ниже описан Kotlin-контракт между компонентами.

## Вход

`PracticeTask` в `:domain:practice`:

| Поле | Назначение |
| --- | --- |
| `taskId: String` | Идентификатор конкретного задания/попытки, заданный вызывающим компонентом |
| `russianWord: String` | Слово или значение на русском |
| `kanji: List<KanjiTask>` | Непустая последовательность ячеек в порядке слова |
| `timeLimitMs: Long? = null` | Лимит на всё слово в миллисекундах; `null` — без ограничения, заданное значение строго положительное |

Каждый `KanjiTask` содержит:

- `occurrenceId: String` — идентификатор позиции, уникальный внутри задания. Два одинаковых кандзи имеют разные позиции и отдельные истории/время.
- `kanjiId: KanjiId` — независимый от источника ключ самого знака. Мэппинг на файл KanjiVG или другой источник выполняется адаптером.
- `mode: EntryMode` — `User` (нужен ввод) либо `Prefilled` (показывается готовый эталон, ввод и выбор отключены).

Пустые идентификаторы и русское слово, пустой список, повторяющиеся `occurrenceId` и неположительный лимит отклоняются при создании контракта. Идентификаторы знаков повторяться могут.

Пример контракта короткого задания:

```kotlin
PracticeTask(
    taskId = "demo-library",
    russianWord = "Библиотека",
    kanji = listOf(
        KanjiTask("library-0", KanjiId("u56f3"), EntryMode.User),      // 図
        KanjiTask("library-1", KanjiId("u66f8"), EntryMode.User),      // 書
        KanjiTask("library-2", KanjiId("u9928"), EntryMode.Prefilled), // 館
    ),
)
```

Ключи `u56f3` и т. п. — выбор демонстрационного host, не формат, навязываемый экраном. Для нового задания host создаёт новый screen-scoped ViewModel с ключом конкретной попытки. При повторном показе того же задания для новой попытки нужен новый ключ/экземпляр владельца состояния.

## Выход

`PracticeResult` передаётся в `onResult`:

| Поле | Назначение |
| --- | --- |
| `taskId` | Связь результата с заданием/попыткой |
| `russianWord` | Русское слово из входа |
| `status: AnswerStatus` | Итог задания |
| `kanji: List<KanjiResult>` | Результат каждой позиции в исходном порядке |
| `elapsedMs: Long` | Суммарное время слова, включая фон |

`AnswerStatus`:

- `Correct` — все требуемые знаки подтверждены анализатором, подсказки не использовались.
- `Assisted` — задание завершено с использованием подсказки. Факт подсказки сохраняется даже после отмены и последующего правильного ввода.
- `Skipped` — пользователь пропустил слово.
- `TimedOut` — истёк установленный лимит.

`KanjiResult` содержит `occurrenceId`, `kanjiId`, исходный `mode`, текущий `status`, `elapsedMs`, `sample: WritingSample` и `hintUsed`. Статусы ячейки: `Empty`, `Editing` (не проверено), `Correct`, `Incorrect`, `Prefilled`. При пропуске и таймауте статусы ячеек сохраняются: например, весь ответ пропущен, но один знак уже правильный, другой не проверен.

Передаются текущие завершённые пользовательские штрихи в координатах 0…1. Незавершённый жест при уходе/таймауте отменяется и не попадает в результат. Подсказка включает бледный эталон под пользовательскими штрихами, не меняя пользовательский `sample`. При необходимости истории всех попыток потребуется отдельный контракт статистики.

Статусы — типизированные перечисления; новые состояния можно добавить в доменный контракт, явно обновив обработчики. Формат сериализации/обратной совместимости внешнего хранилища пока не фиксируется.

## Время

Согласованные правила:

1. Лимит действует на всё слово и по умолчанию отсутствует.
2. Отсчёт начинается при первом показе экрана и продолжается при сворачивании и блокировке устройства. При возвращении монотонное время пересчитывается сразу; истёкший лимит завершает задание до возобновления ввода. UI-тикер и проверка ввода в фоне приостанавливаются. Сохранение после уничтожения процесса пока не реализовано.
3. Время ячейки — суммарное время, пока она выбрана, включая размышление, исправления, ожидание проверки и время в фоне. Возврат к ячейке продолжает её счётчик.
4. Предзаполненные ячейки не выбираются и имеют время ввода 0. После выполнения всего слова таймер останавливается; начало нового жеста возобновляет учёт, если пользователь исправляет ответ.
5. При таймауте время обрезается точно по лимиту, ввод блокируется, выдаётся `TimedOut`.
6. Пропуск и завершение фиксируют результат один раз; последующие действия не меняют результат.

ViewModel передаёт доменному сценарию интервалы монотонного времени (`SystemClock.elapsedRealtime`), а не часы календаря. Задержка кадров не накапливает погрешность счётчиком «плюс одна секунда».

## Подключаемые зависимости

Два независимых интерфейса находятся в domain:

```kotlin
fun interface KanjiChecker {
    suspend fun check(request: CheckRequest): CheckVerdict
}

fun interface KanjiReferenceSource {
    suspend fun load(id: KanjiId): ReferenceDrawing?
}
```

В debug из подробностей проверки формы открывается отдельное [окно отладки](debug-inspector.md) с причинами ошибок, компенсациями, настройками и метриками. Закрытая отладка не занимает место в компоновке. Данные привязаны к ревизии; в release окно и сбор расширенных метрик отключены.

`CheckRequest` содержит идентификаторы задания/позиции/знака, ревизию и снимок штрихов. Вердикты: `Correct`, `Incorrect`, `Incomplete`, `Unavailable`. UI-PAD не обращается к анализатору. Проверка запускается автоматически через 350 мс после последнего завершённого штриха. Новый жест отменяет ожидающую или выполняющуюся проверку; устаревшие ответы не применяются. Пауза служит только для объединения частых обновлений, а не доказательством завершённости знака: анализатор может вернуть `Incomplete`. Незаконченный знак не объявляется ошибкой только из-за неполного числа штрихов. Кнопки «Проверить» нет. Результат старой ревизии игнорируется; отмена также увеличивает ревизию.

Подключён [локальный анализатор общей формы](shape-checker.md) из `:checker:shape` в debug и release. Количество штрихов должно точно совпасть; порядок не учитывается. Порог покрытия настраивается. Непустой ввод с несовпадающим количеством или недостаточной геометрической оценкой получает `Incorrect`; пустой — `Incomplete`. Для замены анализатора достаточно изменить сборку зависимостей в host.

Источник `:data:kanjivg` содержит весь базовый набор: 6 984 SVG. Эталоны доступны без сети и докачки. Адаптер читает StrokePaths для геометрии и StrokeNumbers для подписей подсказки; переводит кривые в нейтральные координаты 0…1. Совместимость всех встроенных файлов проверяется инструментальным тестом. Отсутствующий эталон означает недоступность проверки, а не ошибку пользователя.

## Сборка экрана и границы модулей

```text
:app ───────────────→ :feature:practice ─→ :domain:practice ─→ :domain:handwriting
  │                         │
  │                         └──────────→ :core:writingpad ─→ :domain:handwriting
  ├────────────────→ :data:kanjivg ─────→ :domain:practice
  └────────────────→ :core:designsystem
```

- `PracticeSession` реализует бизнес-правила, истории, время, завершение и защиту от устаревших проверок; это чистый Kotlin/JVM.
- `PracticeViewModel` получает задание, источник и анализатор через конструктор, управляет lifecycle и корутинами, отдаёт read-only StateFlow.
- `PracticeRoute(viewModel, onResult, onBack)` не привязан к Navigation или Activity. Host владеет ViewModel и выбирает переход после результата.
- `PracticeScreen` получает только состояние, события и callbacks. Внутри выделены UI-PROMPT, UI-STRIP/UI-CELL, UI-STATUS, UI-TOOLS и UI-ACTIONS.
- Надпись «Напишите кандзи» убрана; вводное объяснение планируется отдельным туториалом.
- Единственная основная кнопка — «Далее»: она доступна только после выполнения всех ячеек и при отсутствии активного жеста/проверки. Непроверенный или ошибочный ввод её не включает. Нажатие выдаёт результат текущего слова; следующее слово выбирает host. Подсказка не выполняет знак: нужен правильный пользовательский ввод.
- Нижняя панель действий закреплена над системной навигацией. Сообщение о недоступной проверке также находится в этой панели, вне прокручиваемого содержимого и с доступным объявлением изменения. На коротком экране содержимое прокручивается; размер поля не зависит от длины слова или статуса. Длинное русское значение переносится без обрезания, при необходимости экран прокручивается.
- Черновик и истории переживают смену конфигурации благодаря ViewModel. Постоянное сохранение после уничтожения процесса/закрытия Activity пока не реализовано; будущий coordinator/repository должен решать эту задачу. «Назад» не равнозначно «Пропустить» и не выдаёт итог ответа.
- `onResult` вызывается один раз за жизнь ViewModel. Для надёжной записи статистики вызывающий компонент должен принимать результаты идемпотентно по идентификатору попытки.

Прогресс группы, очередь заданий, база данных и навигационная библиотека в feature не включены. Демо-host показывает краткий итог полученного результата.

## Текущая интеграция

MainActivity создаёт фиксированное задание «Электроэнцефалография»: 脳波検査, три пользовательских ячейки и одна предзаполненная. Наличие выбранной тренировки на главной пока не означает передачу её параметров в этот host. Итог — демонстрационный экран одного задания. Очередь, итог группы и постоянное восстановление тренировки требуют отдельной реализации.

Слой отображения получает локализованное `wordLabel`. Имя `russianWord` сохранено в текущем Kotlin-контракте; оно не разрешает зависимость бизнес-логики от русского текста или хранение новых переводов в отдельных языковых столбцах. См. [локализацию](localization.md).

Верхняя панель содержит название и таймер, видимой кнопки возврата пока нет. Подробности проверки открываются по нажатию показателей, настройки — из подробностей. UI-композиция и её нерешённые вопросы описаны только в [экранной спецификации](../design-system/05-screens/practice/README.md), а не в хронологии макетов.

## Проверки

Нужны проверки независимых историй, инвалидирования результата при новом вводе, отбрасывания старого ответа, таймаута/фонового времени, накопительного учёта помощи и однократной доставки результата. Доступность «Далее» проверяется для всех обязательных ячеек, а не одного успешного знака.

```sh
./gradlew :domain:practice:test
./gradlew :feature:practice:connectedDebugAndroidTest :core:writingpad:connectedDebugAndroidTest
./gradlew :feature:practice:lintDebug :data:kanjivg:lintDebug :app:lintDebug :app:assembleDebug
```

Это команды проверки, а не заявление об их выполнении. Для текущего аудита подтверждены debug-сборка и [съёмка в эмуляторе](../design-system/01-audit/captures/2026-11-01/README.md); полноценная регрессия не выполнялась.
