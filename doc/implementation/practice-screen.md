# Экран одного слова: контракт и реализация

Статус: реализован экран одного задания; host PRACTICE запускает тренировку из активного рецепта, итерирует задания и пишет прогресс в Room. Дизайн: [SCR-KANJI-PRACTICE](../design-system/05-screens/practice/README.md). Требования: [архитектура](../architecture.md).

Экран отвечает за одно задание, а не за группу слов. Внешний компонент выбирает следующее задание, хранит прогресс группы и принимает результат. Формат файла/базы заданий пока не определён: ниже описан Kotlin-контракт между компонентами.

## Вход

`PracticeTask` в `:domain:practice`:

| Поле | Назначение |
| --- | --- |
| `taskId: String` | Идентификатор конкретного задания/попытки, заданный вызывающим компонентом |
| `russianWord: String` | Слово или значение на русском |
| `kanji: List<KanjiTask>` | Непустая последовательность ячеек в порядке слова |
| `timeLimitMs: Long? = null` | Лимит на всё слово в миллисекундах (`seconds_per_symbol × practice-символы`); `null` — без ограничения, заданное значение строго положительное |
| `reading: String = ""` | Японское чтение слова (кана); пустая строка — host не передал чтение, UI его не показывает |

Каждый `KanjiTask` содержит:

- `occurrenceId: String` — идентификатор позиции, уникальный внутри задания. Два одинаковых кандзи имеют разные позиции и отдельные истории/время.
- `kanjiId: KanjiId` — независимый от источника ключ самого знака. Мэппинг на файл KanjiVG или другой источник выполняется адаптером.
- `mode: EntryMode` — `User` (нужен ввод) либо `Prefilled` (уже заполненная позиция: эталон кандзи или литера кана/знака без ввода и выбора). Предзаполненная позиция считается выполненной сама по себе; рисунок эталона нужен только для отображения, когда он есть.

Какие позиции требуют ввода при старте из рецепта — единый список правил: [training-input-rules.md](training-input-rules.md) (`TrainingInputRules`).

Пустые идентификаторы и русское слово, пустой список, повторяющиеся `occurrenceId` и неположительный лимит отклоняются при создании контракта. Идентификаторы знаков повторяться могут.

Пример контракта короткого задания:

```kotlin
PracticeTask(
    taskId = "demo-library",
    russianWord = "Библиотека",
    kanji = listOf(
        KanjiTask("library-0", KanjiId("u56f3"), EntryMode.User),      // 図
        KanjiTask("library-1", KanjiId("u66f8"), EntryMode.User),      // 書
        KanjiTask("library-2", KanjiId("u9928"), EntryMode.Prefilled), // 館
    ),
)
```

Ключи `u56f3` и т. п. — выбор демонстрационного host, не формат, навязываемый экраном. Для нового задания host создаёт новый screen-scoped ViewModel с ключом конкретной попытки. При повторном показе того же задания для новой попытки нужен новый ключ/экземпляр владельца состояния.

## Выход

`PracticeResult` передаётся в `onResult`:

| Поле | Назначение |
| --- | --- |
| `taskId` | Связь результата с заданием/попыткой |
| `russianWord` | Русское слово из входа |
| `status: AnswerStatus` | Итог задания |
| `kanji: List<KanjiResult>` | Результат каждой позиции в исходном порядке |
| `elapsedMs: Long` | Суммарное время слова, включая фон |

`AnswerStatus`:

- `Correct` — все требуемые знаки подтверждены анализатором, подсказки не использовались.
- `Assisted` — задание завершено с использованием подсказки. Факт подсказки сохраняется даже после отмены и последующего правильного ввода.
- `Skipped` — пользователь пропустил слово.
- `TimedOut` — истёк установленный лимит.

`KanjiResult` содержит `occurrenceId`, `kanjiId`, исходный `mode`, текущий `status`, `elapsedMs`, `sample: WritingSample` и `hintUsed`. Статусы ячейки: `Empty`, `Editing` (не проверено), `Correct`, `Incorrect`, `Prefilled`. При пропуске статусы ячеек сохраняются как были. При таймауте незавершённые practice-ячейки (`Empty` / `Editing`) становятся `Incorrect` (эталон рисуется кистью в поле ввода, как при провале по лимиту подсказок — красный слой с номерами черт), уже `Correct` / `Incorrect` / `Prefilled` не меняются; спойлеры открываются на экране для ознакомления (UI `readingRevealed`), но таймаут сам не выставляет `readingHintUsed` и `translationHintUsed`: в истории остаются только подсказки, которые ученик открыл сам до дедлайна ([hint-scoring.md](hint-scoring.md)); ввод и правки блокируются, переключение между пользовательскими ячейками остаётся для просмотра эталона, «Далее» разблокируется, `TimedOut` фиксируется только по «Далее».

Передаются текущие завершённые пользовательские штрихи в координатах 0…1. Незавершённый жест при уходе/таймауте отменяется и не попадает в результат. Подсказка включает бледный эталон под пользовательскими штрихами, не меняя пользовательский `sample`. При необходимости истории всех попыток потребуется отдельный контракт статистики.

Статусы — типизированные перечисления; новые состояния можно добавить в доменный контракт, явно обновив обработчики. Формат сериализации/обратной совместимости внешнего хранилища пока не фиксируется.

## Время

Согласованные правила:

1. Лимит действует на всё слово и по умолчанию отсутствует.
2. Отсчёт начинается при первом показе экрана и продолжается при сворачивании и блокировке устройства. При возвращении монотонное время пересчитывается сразу; истёкший лимит завершает задание до возобновления ввода. UI-тикер и проверка ввода в фоне приостанавливаются. Сохранение после уничтожения процесса пока не реализовано.
3. Время ячейки — суммарное время, пока она выбрана, включая размышление, исправления, ожидание проверки и время в фоне. Возврат к ячейке продолжает её счётчик.
4. Предзаполненные ячейки не выбираются и имеют время ввода 0. После выполнения всего слова таймер останавливается; начало нового жеста возобновляет учёт, если пользователь исправляет ответ.
5. При таймауте время обрезается точно по лимиту; незавершённые practice-ячейки → `Incorrect`, spoiler чтения открывается, ввод и подсказки по знакам блокируются, эталон выбранной ячейки рисуется кистью в поле ввода, переключение ячеек для просмотра остаётся, «Далее» активируется; `TimedOut` пишется только после «Далее».
6. Пропуск и завершение фиксируют результат один раз; последующие действия не меняют результат.

ViewModel передаёт доменному сценарию интервалы монотонного времени (`SystemClock.elapsedRealtime`), а не часы календаря. Задержка кадров не накапливает погрешность счётчиком «плюс одна секунда».

## Подключаемые зависимости

Два независимых интерфейса находятся в domain:

```kotlin
fun interface KanjiChecker {
    suspend fun check(request: CheckRequest): CheckVerdict
}

fun interface KanjiReferenceSource {
    suspend fun load(id: KanjiId): ReferenceDrawing?
}
```

В debug из подробностей проверки формы открывается отдельное [окно отладки](debug-inspector.md) с причинами ошибок, компенсациями, настройками и метриками. Закрытая отладка не занимает место в компоновке. Данные привязаны к ревизии; в release окно и сбор расширенных метрик отключены.

`CheckRequest` содержит идентификаторы задания/позиции/знака, ревизию и снимок штрихов. Вердикты: `Correct`, `Incorrect`, `Incomplete`, `Unavailable`. UI-PAD не обращается к анализатору. Проверка запускается автоматически через 350 мс после последнего завершённого штриха. Новый жест отменяет ожидающую или выполняющуюся проверку; устаревшие ответы не применяются. Пауза служит только для объединения частых обновлений, а не доказательством завершённости знака: анализатор может вернуть `Incomplete`. Незаконченный знак не объявляется ошибкой только из-за неполного числа штрихов. Кнопки «Проверить» нет. Результат старой ревизии игнорируется; отмена также увеличивает ревизию. Когда все включённые проверки принимают текущий знак (`Correct`), выбор автоматически переходит к следующей ещё не выполненной пользовательской ячейке; предзаполненные пропускаются. Если любой из включённых чекеров даёт `Unavailable` (таймаут, отсутствие модели ML Kit, отсутствие эталона в базе), общий агрегированный вердикт `CombinedKanjiChecker` остаётся `Unavailable`, ячейка остаётся в статусе `Editing` и не засчитывается как верная. Если такой ячейки нет, выбор остаётся на принятом знаке, и доступна «Далее».

Подключён [локальный анализатор общей формы](shape-checker.md) из `:checker:shape` в debug и release. Количество штрихов должно точно совпасть; порядок не учитывается. Порог покрытия настраивается. Непустой ввод с несовпадающим количеством или недостаточной геометрической оценкой получает `Incorrect`; пустой — `Incomplete`. Для замены анализатора достаточно изменить сборку зависимостей в host.

Источник `:data:kanjivg` содержит весь базовый набор: 6 984 SVG. Эталоны доступны без сети и докачки. Адаптер читает StrokePaths для геометрии и StrokeNumbers для подписей подсказки; переводит кривые в нейтральные координаты 0…1. Совместимость всех встроенных файлов проверяется инструментальным тестом. Отсутствующий эталон означает недоступность проверки, а не ошибку пользователя.

## Сборка экрана и границы модулей

```text
:app ───────────────→ :feature:practice ─→ :domain:practice ─→ :domain:handwriting
  │                         │
  │                         └──────────→ :core:writingpad ─→ :domain:handwriting
  ├────────────────→ :data:kanjivg ─────→ :domain:practice
  └────────────────→ :core:designsystem
```

- `HandwritingTraining` реализует бизнес-правила, истории, время, завершение и защиту от устаревших проверок; это чистый Kotlin/JVM.
- `PracticeViewModel` получает задание, источник и анализатор через конструктор, управляет lifecycle и корутинами, отдаёт read-only StateFlow.
- `PracticeRoute(viewModel, onResult, onBack)` не привязан к Navigation или Activity. Host владеет ViewModel и выбирает переход после результата.
- `PracticeScreen` получает только состояние, события и callbacks. Внутри выделены UI-PROMPT, UI-STRIP/UI-CELL, UI-STATUS, UI-TOOLS и UI-ACTIONS.
- Надпись «Напишите кандзи» убрана; вводное объяснение планируется отдельным туториалом.
- Единственная основная кнопка — «Далее» (во время ввода пока не все знаки зафиксированы отображается контурная «Пропустить», `OutlinedButton` цвета `error` с контуром `error`, предупреждающая о снижении балла за задание): активна сразу. Когда все знаки слова зафиксированы (`isResolved`) или истёк дедлайн таймера (`timedOut`), кнопка меняет надпись на «Далее». При этом, если все знаки верны (`isComplete`), кнопка становится позитивной (Primary `FilledButton`); если слово завершено с ошибками (`Incorrect`) или по таймауту, кнопка использует приглушенный стиль ошибки (`errorContainer` / `onErrorContainer`), и её нажатие завершает слово с частичным начислением баллов за верные знаки и фиксацией ошибки. Таймер слова останавливается, когда все знаки зафиксированы (`isResolved`). Настройка `RecognitionSettings.autoAdvanceOnSuccess` (`SETTINGS.W05`, включена по умолчанию): при верном решении всех знаков без исправимых штрафов (`isComplete` и `!hasFixablePenalty`, без таймаута) ViewModel автоматически вызывает `submit`, host переходит к следующему заданию без нажатия «Далее». Использование подсказок необратимо и не блокирует автопереход; мягко принятая форма со штрафом оставляет кандзи выбранным для перерисовки и требует ручного нажатия «Далее». Ошибка, таймаут и ручной пропуск слова также требуют нажатия кнопки действия. В строке проверок `PRACTICE.W06` колонка «Помощь» отображает общий счётчик использованных подсказок задания (`0/3…3/3`), объединяющий подсказки в шапке (чтение, перевод) и подсказки знака/черты; тап открывает диалог остатка и причин снижения оценки без формул. При исчерпании лимита подсказки просто заканчиваются, самостоятельный ввод не блокируется.
- Нижняя панель действий закреплена над системной навигацией. Сообщение о недоступной проверке также находится в этой панели, вне прокручиваемого содержимого и с доступным объявлением изменения. На коротком экране содержимое прокручивается; размер поля не зависит от длины слова или статуса. Длинное русское значение переносится без обрезания, при необходимости экран прокручивается.
- Черновик и истории переживают смену конфигурации благодаря ViewModel. Допущение: постоянное сохранение после уничтожения процесса/закрытия Activity или выхода через «Назад» намеренно не восстанавливает остаток таймера для текущего незавершённого слова — приложение предназначено для самостоятельного обучения учеником для себя, а не строгого тестирования. «Назад» не равнозначно «Пропустить» и не выдаёт итог ответа.
- `onResult` вызывается один раз за жизнь ViewModel. Для надёжной записи статистики вызывающий компонент должен принимать результаты идемпотентно по идентификатору попытки.

Прогресс группы, очередь заданий, база данных и навигационная библиотека в feature не включены. Демо-host показывает краткий итог полученного результата.

## Текущая интеграция

Host собирает очередь через `shuffledCycles` (`shuffled_cycles`) после выбора рецепта на `HOME.01`: длина — `taskCount` или весь пригодный пул (слова без записываемых кандзи отбрасываются до отбора). Если пул пуст, PRACTICE не открывается: на `HOME.01` показывается диалог, тренировка не создаётся. При старте тренировки текущее значение `RecognitionSettings.maxNextStrokeHints` копируется в доменный агрегат `Training`. Старт новой тренировки в одной транзакции прерывает предыдущую `in_progress`. Слова проходятся по очереди; после каждого задания (и при interrupt/complete) состояние пишется в Room асинхронно на IO через `KanjiApplication.persistenceScope` — без записи на каждый штрих и без отмены сохранения при закрытии экрана. Если фоновое сохранение завершается ошибкой, ошибка подробно логируется (уровень `SEVERE`), пользователю ненавязчиво выводится всплывающее уведомление (Toast), а переход к следующему слову `advance()` не блокируется. Выход с PRACTICE при незавершённой оставляет `in_progress` (HOME предлагает продолжить или начать новую). «Продолжить» восстанавливает очередь из Room без ink текущего знака. После последнего задания открывается PRACTICE.01 ([оценка](training-grade.md)), где расчёт баллов опирается на сохранённый бюджет подсказок. Схема — [trainings.md](../database/trainings.md).

Слой отображения получает локализованное `wordLabel`. Имя `russianWord` сохранено в текущем Kotlin-контракте; оно не разрешает зависимость бизнес-логики от русского текста или хранение новых переводов в отдельных языковых столбцах. См. [локализацию](localization.md).

Верхняя панель: «Назад», название и таймер. «Назад» и системный Back открывают подтверждение прерывания (`PRACTICE.D04`): прогресс сохраняется как `in_progress`, с HOME можно продолжить. Подробности проверки открываются по нажатию показателей; настройки проверки — в SETTINGS, не из PRACTICE. UI-композиция описана в [экранной спецификации](../design-system/05-screens/practice/README.md).

## Проверки

Нужны проверки независимых историй, инвалидирования результата при новом вводе, отбрасывания старого ответа, таймаута/фонового времени, накопительного учёта помощи и однократной доставки результата. Доступность «Далее» проверяется для всех обязательных ячеек, а не одного успешного знака.

```sh
./gradlew :domain:practice:test
./gradlew :feature:practice:connectedDebugAndroidTest :core:writingpad:connectedDebugAndroidTest
./gradlew :feature:practice:lintDebug :data:kanjivg:lintDebug :app:lintDebug :app:assembleDebug
```

Это команды проверки, а не заявление об их выполнении. Для текущего аудита подтверждены debug-сборка и [съёмка в эмуляторе](../releases/1.0.0.md); полноценная регрессия не выполнялась.

## Единый показатель помощи

В обоих режимах показатель помощи показывает использованные обращения
`0/3…3/3`. После принятия без помощи он зелёный, при частичном расходе
жёлтый, при полном красный. Лимит 0 отображается как `0/0` и не считается расходом.
Тап открывает диалог остатка и балла, не вызывает и не расходует помощь.
Нижние кнопки в режиме «Кнопки» остаются без бейджа.

«Далее» отражает всё задание: зелёная без помощи, жёлтая при частичном
расходе помощи, текстовой подсказке или мягком принятии формы; красная
при полном расходе помощи хотя бы на одном знаке, ошибке или таймауте.
Красный расход не обнуляет балл: формула верного знака — `0.8^k × shapeFactor`.

Форма с недобором строго меньше настроенного допуска (по умолчанию 10 п.п.) до настроенного порога принимается
со штрафом 20%, если нет других ошибок. Знак и Черты остаются строгими.
Форма и принятый с понижением балла знак жёлтые. В диалоге объясняются допуск и штраф.
Признак `acceptedWithPenalty` отчёта проходит в `shapeAcceptedWithPenalty`
ячейки и `KanjiResult`; при правке или инвалидировании очищается.
В истории он сохраняется в `shape_verdict=accepted_with_penalty`.

## Автопереход при штрафе

Использование помощи не блокирует автопереход: подсказки необратимы и их нельзя
исправить. Автопереход приостанавливается только тем, что пользователь может
исправить — в частности, мягким принятием формы (`hasFixablePenalty`). Если форма знака
принята с понижением балла, ячейка остаётся выбранной для возможности перерисовать её лучше.
При отсутствии исправляемых штрафов автопереход к следующему кандзи и к следующему заданию
срабатывает автоматически (при включённых соответствующих настройках).
Счётчик «Помощь» использует ту же типографику значений, что остальные показатели:
`titleLarge`, 22 sp, `SemiBold`, с одинаковой высотой строки.
