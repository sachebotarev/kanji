# Компоненты тренировки

Идентификаторы UI-* и якоря стабильны. Ниже — назначение и поведение, а не окончательная визуальная шкала. [Экран](../05-screens/practice/README.md), [контракт Android](../../implementation/practice-screen.md).

<a id="visual-style"></a>
## UI-STYLE — Визуальный стиль

Общий характер и роли берутся из [основ](../03-foundations/README.md). Цвет не является единственным способом показать результат. Выбранность ячейки и правильность ответа независимы.

<a id="training-progress"></a>
## UI-PROGRESS — Прогресс тренировки

Позиция и прогресс группы принадлежат host тренировки. Пройденные задания включают выполненные и пропущенные, качество результата учитывается отдельно. Android-host ведёт очередь из рецепта и в заголовке показывает «Практика N из M»; HTML-счётчик в макете иллюстративный и не является источником статистики.

<a id="word-prompt"></a>
## UI-PROMPT — Задание

Локализованное значение, слово, выражение или предложение. До двух строк по центру: при обрезке в конце последней строки inline «… ещё» / «… more» (как в Instagram/YouTube); тап открывает полный перевод в диалоге, без лишней вертикальной полосы. Вертикаль экрана PRACTICE должна укладываться без прокрутки. Над рядом ячеек японское чтение (`PracticeTask.reading`) по умолчанию закрыто анимированным шумом (spoiler), по центру; нажатие снимает зашумление и засчитывается как одна использованная подсказка. Образец знака — отдельная подсказка в нижней панели рядом с «Далее».

<a id="kanji-cell"></a>
## UI-CELL — Ячейка кандзи

Показывает пользовательский ввод или разрешённый предзаполненный эталон. Состояния: пусто, редактирование, непроверено, верно, ошибка, предзаполнено. При `Incorrect` с собственным рисунком ячейка сохраняет пользовательские штрихи цветом ошибки; эталон (или глиф) показывается только если ввода нет или исчерпан лимит подсказок. Выбор независим от результата. Начало жеста временно заменяет оформление результата на ввод, отмена возвращает прежнее; новый штрих инвалидирует проверку.

Некандзи из написания слова (кана вроде お в お寺) не пропускаются: они занимают ячейку в режиме `Prefilled` и показываются глифом, без ввода. Пробелы в написании в ряд не попадают.

Текущая геометрия Android: сторона ячейки подбирается по ширине ряда (макс. 64 dp), чтобы **пять** знаков гарантированно помещались без прокрутки; высота = сторона + 8 dp подчёркивания, радиус до 12 dp. Активный ввод и выбор — `secondary` / `secondaryContainer` (холодный сине-серый), чтобы не путать с верным (`primary`) и ошибкой (`error`). `tertiary` для выбора не использовать. Это факты реализации, не финальная шкала. Предзаполненная ячейка не выбирается и не редактируется. Доступное описание сообщает номер, результат и выбор, не раскрывая скрытый ответ.

<a id="kanji-strip"></a>
## UI-STRIP — Ряд ячеек

Одна горизонтальная строка: до пяти знаков — без прокрутки, по центру; длиннее — жестовая прокрутка от левого края. Намёк на продолжение ряда: лёгкий peek следующей ячейки и мягкий edge-fade по видимым краям через альфа-маску (не оверлей цветом фона), выровнен по верху ячеек, без стрелок. Прокрутка не меняет выбор. Ячейка текущего ввода всегда удерживается в видимой области вне зоны fade. Истории разных позиций не смешиваются. При вердикте ячейка коротко вспыхивает (`primary` / `error`) и оседает в контейнерный цвет; после успеха выбор плавно переходит к следующей незавершённой пользовательской ячейке.

<a id="status-row"></a>
## UI-STATUS — Результаты проверок

Над полем три компактных нажимаемых показателя: читаемость, форма, черты. Строка уже поля письма и ближе к нему, **фиксированной высоты** — появление распознанного знака ML Kit не меняет геометрию и не сжимает поле письма (смена размера поля отменяет активный жест). Показатели: распознанный знак, процент совпадения формы и число завершённых черт. Ожидание, проверка, неполный ввод, ошибка, успех, отключение и недоступность различаются в доступном описании. Детали открываются по нажатию.

Визуальное различие статусов помимо цвета требует проработки; рисованные мару/бацу в HTML — предложение, не утверждённое правило Android. Время показывает отдельный HeaderTaskTimer, а не прежняя единая строка номера/вердикта/времени.

<a id="writing-pad"></a>
## UI-PAD — Поле письма

Отдельный компонент с нормализованными штрихами, горизонтальными, вертикальными и диагональными направляющими, пользовательским вводом и независимыми слоями подсказки/диагностики. Не содержит бизнес-проверки, навигации или репозитория. Размер поля не зависит от вердикта. На экране практики сторона квадрата берётся по ширине контейнера; строка результатов и иконки отмены/очистки остаются вне поля и не перекрывают холст. [Вход, события и геометрия](../../implementation/ui-pad.md).

<a id="tool-panel"></a>
## UI-TOOLS — Подсказка, отмена, очистка

Подсказка — помощь по знаку, не принятие ответа и не раскрытие чтения. Режим задаётся в настройках проверки: полный бледный эталон с номерами черт или жёлтая анимация следующей черты. В обоих режимах каждое включение считается; при достижении лимита (по умолчанию 3) знак дорисовывается целиком красным с номерами и становится неверным. Отмена удаляет последний завершённый штрих выбранной ячейки; очистка — её ввод. В нижней панели три круглые кнопки только с иконками (отмена, очистка, подсказка); оставшееся место занимает «Далее». Активность и доступность обозначаются явно. Детали — [алгоритм подсказки](../../implementation/hints.md).

<a id="bottom-actions"></a>
## UI-ACTIONS — Инструменты и переход

Слева — три круглые иконки: отмена, очистка, подсказка. Отдельной кнопки «Пропустить» нет: «Далее» занимает оставшуюся ширину справа и активна, когда каждая ячейка уже Correct, Incorrect или Prefilled (нет активного жеста/проверки). Если все приняты — итог Correct/Assisted; если есть Incorrect — слово завершается как пропуск. Прогресс «N из M» — часть основного заголовка («Практика N из M»). Нижняя область и сообщение о недоступной проверке остаются достижимыми при прокрутке и системных панелях.
