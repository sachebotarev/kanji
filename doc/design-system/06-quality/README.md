# Проверка и повторное согласование каталога

Текущие статусы согласования находятся в единственном [реестре](../theme/screens.json). Все экраны реестра согласованы 2026-11-07, **кроме** `SETTINGS` и `SETTINGS.01`. [Целевой контракт Android](../../implementation/approved-ui-handoff.md) не означает завершённую реализацию.

## Что проверять в макете

- Реальные данные обоих учебников, сохранение написания, чтения, выражений и предложений.
- Читаемость каны, переводов, классификаций и подписей в двух темах.
- Назначение выбора, выбранность, независимый сброс условий и возврат.
- Выбор главы для кандзи без количества слов, выбор для слов с нужным количеством.
- Связанные слова: понятные группы и количества без неоднозначной доли «из N».
- Полные названия ключей до выбора и легенды учебных номеров.
- ru/en, русский fallback, ширины 360/411/480, масштаб 100/130/160%.
- Пустые результаты, загрузку, ошибку и доступное следующее действие.

Статусы и сообщения об изменениях находятся вне интерфейса телефона. Проверка содержимого: `node doc/design-system/prototypes/textbooks/test_content.cjs`. Браузерный сценарий `test_browser.cjs` требует доступный пакет Playwright и установленный Chrome; он проверяет все маршруты и не записывает согласование.

## Что проверять в Android

HTML не моделирует IME, системный Back, TalkBack, жизненный цикл и физику Compose. Для этих сценариев нужны нативные проверки. Активные контрактные требования: области нажатия не менее 48 dp, сохранение системного масштаба текста, независимые позиции/поиск вкладок, восстановление простых значений без помещения каталога в Bundle и отсутствие потери пользовательских данных.

Последние нативные результаты: [рефакторинг presentation](../../releases/1.0.0.md). Проверки показывают конкретный охват и ограничения. Успешный тест или совпадение картинки не меняют статус дизайна автоматически.
