# Поддержка макетов и согласования

В активной документации хранится одна текущая редакция. Для каталога источник статусов — [review-status.json](05-screens/catalog/review-status.json). Он содержит устойчивые ID экранов, маршруты и переводимые пояснения с `language_tag`. Прототип читает реестр; `python3 doc/design-system/review_catalog.py` обновляет Markdown и обзорную страницу.

Изменение экранной композиции, подписей, состояния или общего компонента требует повторного согласования всех затронутых экранов. До явного решения пользователя статус — `unapproved`. Сборка, тест, экспорт данных и смена браузерной темы не меняют статус. При разрешении пользователя обновляется конкретный перечень экранов в реестре, затем перегенерируется документация.

Текущий каталог полностью передан на повторное согласование. В обзоре указано, что изменено. Материалы `approved/` — исходные снимки предыдущей редакции для сравнения; их нельзя подменять новыми изображениями без изменения статуса.

Размеры и роли находятся в [токенах](03-foundations/README.md), контракты компонентов — в [библиотеке](04-components/README.md), экранные требования — в [реестре](05-screens/catalog/README.md). Изменение общего компонента обновляет спецификации и все затронутые статусы.

HTML — средство просмотра. Android использует Compose по [архитектуре](../architecture.md). Системные IME, Back, жизненный цикл и TalkBack проверяются нативно. Результат проверки указывает среду и ограничения и не объявляет дизайн согласованным.

README описывает актуальный итог. История находится в Git; лицензии, исходные данные и необходимые свидетельства проверок сохраняются. При очистке удаляются недоступные варианты кода и действительно неиспользуемые ресурсы, а не произвольные файлы со статусом untracked.
