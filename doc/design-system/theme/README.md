# Общая тема и статусы просмотрщика

Общая конфигурация дизайн-макета. Радиус полей ввода также экспортируется в Android-ресурс; код экранов, нативные палитры и бизнес-логика не генерируются. Согласованы экраны реестра **кроме** `SETTINGS` и `SETTINGS.01` (2026-11-07). Канонические статусы — в screens.json. [Контракт переноса](../../implementation/approved-ui-handoff.md).

## Изменить цвета

Открыть [экран «Тема приложения»](../prototypes/index.html#theme). Четыре цветовых поля и HEX-ввод меняют Primary, Secondary, Tertiary и Error. Полные светлая/тёмная схемы пересчитываются локально, без внешнего API. Черновик хранится в localStorage браузера и распространяется на открытые вкладки двух просмотрщиков. Можно сбросить черновик и выгрузить JSON.

Для изменения палитры проекта заменить `key_colors` в **[theme-source.json](theme-source.json)** либо сохранить туда выгруженную конфигурацию. Затем из корня репозитория:

```sh
npm ci --prefix doc/design-system/theme --ignore-scripts
npm run build --prefix doc/design-system/theme
```

Генератор создаёт общие `material-theme.css`, `material-theme.json` и локальный модуль пересчёта `material-colors.js` в `prototypes/shared/`. Локальный черновик привязан к исходным key colors: изменение базовой палитры в файле делает старый черновик неактуальным. Кнопка «Исходная палитра» вручную снимает текущий черновик. Для обычного запуска просмотрщика npm не нужен — генерируемые файлы хранятся в проекте.

В той же конфигурации заданы типографическая шкала из 15 ролей, формы, уровни высоты и непрозрачность состояний. UI обращается к семантическим ролям из общей темы; `material-components.css` связывает компоненты и прежние имена переменных с ролями. Экранные CSS отвечают за компоновку, а не объявляют новые палитры.

## Скругление всех полей ввода

Единственное место изменения — **`component_shape.text_field`** в [theme-source.json](theme-source.json). Текущее значение — **16**: dp в Android, CSS px в макете. Оно независимо от радиусов карточек и кнопок.

После изменения выполнить `npm run build --prefix doc/design-system/theme`. Одна команда обновляет:

- `--app-input-corner-radius` в общем CSS и экспорт JSON;
- `core/designsystem/src/main/res/values/input-shape.xml` — генерируемый ресурс, вручную не редактировать.

Нативные текстовые, поисковые, числовые и многострочные поля, включая диалоги, используют `shape = MaterialTheme.inputShape` из `core:designsystem`. Макеты используют общий токен в `material-components.css`. Чекбоксы, радиокнопки, слайдеры и выбор цвета не получают форму текстового поля. Локальные числовые радиусы полей не добавлять.

Проверка синхронизации и всех нативных вызовов: `python3 doc/verification/check-input-shapes.py`. [Проверки и кадры](../../releases/1.0.0.md).

## Изменить статусы

Единственный редактируемый источник — **[screens.json](screens.json)**. В разделе `features` находятся фичи и их названия. У каждого экрана есть ID, фича, модуль, устойчивый ключ/маршрут, `status` и пояснения с `language_tag`. Допустимы `unapproved` и `approved`. Пустые, загружающиеся, ошибочные состояния, диалоги и масштабы наследуют статус своего экрана. Неизвестный экран или ошибка реестра не считаются согласованием.

Единая оболочка просмотрщика и рендереры читают этот файл при загрузке страницы с `cache: no-store`. Для просмотра изменения достаточно обновить страницу; править JavaScript не нужно. Спецификации обновляются до актуального состояния вместе с контрактами; копии реестра не генерируются.

Менять `approved` можно только после явного решения пользователя о соответствующем экране. Перекраска, экспорт JSON, тест и переключение темы не меняют статус автоматически. В браузере нет кнопки, которая объявляет экран согласованным.

## Происхождение и ограничения

Тональные палитры HCT строятся официальной библиотекой `@material/material-color-utilities` 0.4.0. Нейтральные палитры выводятся из hue Primary; chroma задаётся `neutral_chroma` / `neutral_variant_chroma`. Тон `primary-container` можно смягчить через `primary_container_tones` (light/dark), не меняя key colors. Базовые light-цвета primary/secondary/tertiary/error совпадают с выбранными key colors; остальные тона вычисляются. После `npm run build` синхронизировать `KanjiTheme.kt` с `material-theme.json`. Если при ручной настройке пара текста и заливки теряет контраст, редактор показывает предупреждение. Он не выдаёт любой произвольный цвет за гарантированно доступный.

Пакет 0.4.0 имеет некорректный extensionless import в неиспользуемом dynamic-color entrypoint; импортированы непосредственно официальные `TonalPalette`, `Hct` и string utilities. Локальная сборка через esbuild 0.28.2 не меняет зависимости Android. Лицензия Apache-2.0 включена в `material-colors.js.LEGAL.txt`. Проверки и снимки — [отчёт](../../releases/1.0.0.md).

## Единая навигация

[Просмотрщик](../prototypes/index.html#home) — один вход для всех фич. Список фич, экранов и статусы читаются из `screens.json`, код экранов для их изменения не нужен. [Устройство и команды](../prototypes/README.md). `?standalone=1` предназначен только для регрессионных тестов рендереров.
