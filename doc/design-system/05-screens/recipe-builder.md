# Конструктор рецептов

Статус: **конструктор и его общие экраны согласованы пользователем 2026-11-04**. [Реестр](../theme/screens.json), [контракт реализации](../../implementation/approved-ui-handoff.md). HTML-проверки не означают готовый Android. Тренировки и статистика не реализуются на текущем этапе.

Текущий макет RECIPE.01 / RECIPE.02: нейтральные поверхности SurfaceContainer / OnSurface, выбранные варианты SecondaryContainer / OnSecondaryContainer без галочек, интервалы разделов 24 CSS px. Постоянные объяснения объединения источников, повторов и таймера убраны из основной формы. У карточки материала trailing один: в просмотре RECIPE.02 — шеврон (открыть), в редакторе RECIPE.01 — только корзина (удалить); открытие/правка — тап по телу карточки. Счётчик «Доступно: N» на карточке не дублируется: размер пула рецепта показывает «Посмотреть N слов» / «View N words». Это вторичное текстовое действие без шеврона сразу под «Добавить материал» (или под списком в просмотре). Строка скрыта, пока набор пуст. Нажатие открывает отдельный экран со списком в оформлении каталога: написание, чтение и перевод. «Назад» возвращает в черновик или просмотр. В форме «Из учебника» учебник выбирается из постоянного списка радиокарточек без сворачивания в строку смены. Типы материала имеют краткие подписи. Заголовки SELECT включают контекст («Главы · Tobira»). Выход из изменённой формы материала подтверждается так же, как выход из рецепта. Пустое название при сохранении подставляется из состава материалов; в поле — placeholder. «Заданий…» и «Секунд…» — секция «Параметры тренировки» / «Training settings»; в режиме числа — пресеты 10/20/30 и степпер ± без обязательной клавиатуры. На списке RECIPE тело карточки открывает просмотр (шеврон справа); постоянного выбора радиокнопкой нет — рецепт для тренировки выбирается на `HOME.01`. Поле таймера — «Секунд на слово». Настройки «Как показывать слова» нет. Слова выбираются автоматически: до размера набора включительно — случайно без повторов; сверх размера — перемешанными циклами. В интерфейсе пояснения не показываются. Удаление материала можно отменить действием «Отменить», восстанавливающим его на прежнем месте; повторное удаление заменяет доступную отмену. Настройки тренировки в блоке не дублируются. Метка поля «Название» оформлена заголовком 18 CSS px, равнозначным «Учебный материал». Кнопка добавления — «Добавить материал» / «Add material»; режим базового объёма — «По числу слов» / «Match word count». После трёх материалов остальные сворачиваются под «Ещё материалов: N» с раскрытием; расчёт включает все материалы. Удаление обозначено корзиной. В строке материала название отделено от меток глав и условий: все выбранные условия видны без открытия. Ошибки формы показываются у соответствующих полей: обводка роли Error, короткий supporting text и значок, а не общая строка внизу. Поля имеют aria-invalid и связь aria-describedby с сообщением; при сохранении фокус и прокрутка переходят к первой ошибке. Это HTML-представление Material-состояния, не реализация Android TextField.

Сохранение — закреплённая Extended FAB «Сохранить» / «Save» со значком сохранения справа снизу, как создание в RECIPE. Форма прокручивается независимо; нижний отступ и scroll-padding 112 CSS px позволяют поднять последние поля и ошибки над FAB. Кнопка доступна без прокрутки к концу.
 Android-конструктор использует Room 6 и общие Compose-селекторы; текущие проверки и ограничения перечислены в [отчёте рефакторинга](../../verification/recipe-terminology.md). [Проверки и ограничения](../../verification/recipe-builder/README.md). [Открыть макет](../prototypes/index.html#recipe-builder). [Модель данных](../../database/recipes.md).

## 1. Сценарии пользователя

1. **Создание и настройка рецепта**:
   - Пользователь переходит с Главного экрана (`:feature:dashboard`) через кнопку «Выбрать» к экрану «Конструктор рецептов».
   - Нажимает «Создать рецепт» (или открывает существующий через просмотр и правит его).
   - Задаёт название, формирует состав учебного материала из одного или нескольких источников и настраивает параметры тренировки (число заданий, способ перемешивания и ограничение времени на слово).

2. **Выбор учебного материала (отдельный экран)**:
   - В навигации макета доступны отдельные состояния: [RECIPE.01.02 — добавление](../prototypes/index.html#recipe-builder/RECIPE.01.02), [RECIPE.01.02.01 — изменение](../prototypes/index.html#recipe-builder/RECIPE.01.02.01), [RECIPE.01.03 — слова](../prototypes/index.html#recipe-builder/RECIPE.01.03). Для прямого просмотра используется демонстрационный рецепт с материалом.
   - Добавление и изменение открываются без диалога. «Назад» отбрасывает изменения материала, «Добавить»/«Применить» обновляет черновик рецепта, не сохраняя сам рецепт.
   - Один экран с выбором типа сверху и сменным нижним блоком; обработчики и поля типов разделены в `material-picker.js`:
     - **Из учебника**: список учебников без поиска. После выбора — фильтры «Главы» и «Кандзи», открывающие отдельный экран справочника по образцу фильтров каталога: поиск, действие «Все главы» / «Все кандзи», карточки глав с количеством кандзи и превью знаков либо сетка кандзи. Выбор множественный; возврат ведёт в форму материала. Фильтры не раскрывают самодельный список внутри формы. Компоненты сетки знаков, карточки главы, строки справочника и чипа фильтра вынесены из каталога в `prototypes/shared/catalog-selection.js`; каталог и конструктор вызывают один и тот же код. Конструктор подключает исходные `textbooks/styles.css`, `components.css`, `tokens.css` для справочников, а не собственную имитацию сетки и фильтров. Отличие выбора — поддержка нескольких кандзи и глав с возвратом в материал. Главы выбираются из справочника, не вводятся числовым диапазоном; пустой выбор означает все главы. Сетка кандзи ограничена выбранными главами. Пустой выбор кандзи означает все кандзи выбранных глав.
     - **Из словаря**: единственный личный словарь, без выбора словаря. Строка «Теги» открывает тот же экран выбора тегов, что фильтр словаря и редактор записи: поиск названий, множественный выбор, снятие выбора и плавающее подтверждение. Выбранные теги объединяются по **ИЛИ**, с кандзи — по **И**. Пустой набор тегов не ограничивает слова. «Назад» отменяет изменения выбора; подтверждение обновляет только черновик материала, не фильтр списка словаря. Сохранение материала и рецепта сохраняет `tag_ids`, а не переведённые названия. Строка «Кандзи» использует общий экран выбора с поиском и фильтрами; доступные знаки взяты из личных слов с учётом тегов. Превью и количество слов учитывают оба условия. Управление общими тегами доступно из меню «⋮» общего экрана выбора. Это реализация HTML-макета, не Android/Room.
     - **По кандзи**: все слова каталога и личного словаря без привязки к учебнику или словарю; ограничение только выбранными кандзи. Нейтральная строка «Кандзи» открывает тот же отдельный справочник с поиском и множественным выбором, что и в предыдущих типах материала, но содержит все кандзи. Слово подходит, если содержит хотя бы один выбранный кандзи. Дополнительного переключателя «Слова содержат» нет. Без выбранных знаков доступны все слова. Просмотр слов использует общий виджет; возврат из справочника сохраняет выбор в черновике.
     - **Набор слов**: форма содержит нейтральную навигационную строку «Выбрать слова» с количеством выбранных и общий просмотр результата. Выбор открывается отдельно через `material-filter` в режиме `words`: поиск по написанию, чтению и переводу скрыт под лупой, как в остальных справочниках. Фильтр — кандзи. Отдельный двухпозиционный переключатель «Все / Выбранные» меняет режим просмотра и визуально отделён от фильтров. Действие «Снять выбор» доступно на экранах выбора слов, глав и кандзи: очищает только текущий выбор, не закрывает экран, сохраняет поиск и фильтры; без выбранных элементов отключено. Фильтрации по источникам и учебникам здесь нет. Кандзи выбираются на отдельном вложенном экране общей сеткой каталога; они сужают выдачу, но не меняют выбранные слова. Список слов использует классы каталога. Поиск и фильтры меняют только выдачу, не выбранный набор. «Применить» и возврат ведут в черновик материала с сохранением выбора. Пустая выдача содержит кота с лупой, без сброса выбранных слов. Без слов добавить материал нельзя. Реализация HTML: `prototypes/web/word-picker.js`. В просмотрщике отдельно доступны RECIPE.01.02.02 (главы), RECIPE.01.02.03 (общий выбор кандзи), SELECT.06 (слова); все согласованы 2026-11-04. Фильтр слов по кандзи использует общий экран выбора, без дублирующего пункта навигации. Пустой поиск — состояние экрана слов, не отдельный экран.
   - Списки используют данные каталога. Кандзи и слова сужаются поиском и фильтрами; кнопки «Показать ещё» и искусственного ограничения выдачи нет. Выбор сохраняется при поиске. Учебники показываются списком без поиска. Данные локальные; серверная пагинация не реализована. Ограничения материала представлены отдельными нейтральными навигационными строками без общей плашки, цветной заливки и рамки. Название 18 CSS px, выбранные значения ниже — 14 CSS px в OnSurfaceVariant; справа шеврон. Вся строка открывает справочник. В строках и метках глав видны первые три номера в числовом порядке, затем «Ещё N»; полный выбор доступен в справочнике. Превью кандзи в форме материала и карточках материалов ограничено тремя знаками, затем «Ещё N»; полный выбор виден в справочнике. На карточках рецептов метка кандзи показывает только количество («Кандзи: N»). Ограничение превью не меняет выбранный набор. Без ограничений показано «Все главы» / «Все кандзи». Главы ограничивают доступные кандзи, а кандзи ограничивают справочник глав. При изменении выбора несовместимые выбранные значения исключаются.
   - Черновики разных типов сохраняются при переключении в рамках открытого экрана; в рецепт применяется только активный тип. Смена учебника или глав исключает выбранные кандзи вне нового диапазона. В HTML наборы хранятся в `kanji_ids`, `word_ids`, условие — `kanji_match`; это прототип, не миграция Android-БД.
   - В формах материала (учебник / словарь / кандзи / набор слов) и в просмотре материала используется тот же вторичный виджет «Посмотреть N слов» без шеврона, что и в RECIPE.01 / RECIPE.02. Он открывает слова текущего черновика или материала, а не объединённый набор рецепта; возврат сохраняет черновик без применения. При пустом наборе строка скрыта. В селекторах «Выбрано: N» открывает просмотр выбранных значений, «← Все» возвращает полный список. Главы, ключи, черты и JLPT используют [общий контракт множественных фильтров](catalog/multiselect-filters.md): переключение отметок, подтверждение FAB «Применить», отмена стрелкой назад и плашки с выбранными значениями.
   - Внутри источника разные фильтры пересекаются (**И**), несколько значений одного фильтра объединяются по **ИЛИ**.
   - Разные источники в рецепте объединяются (**ИЛИ**) с автоматическим устранением дубликатов слов.

3. **Лимиты тренировки и порядок заданий**:
   - **Заданий за тренировку**:
     - *«По числу слов»*: тренировка проходит все уникальные слова набора один раз в случайном порядке.
     - *«Задать число»*: можно указать любое целое положительное число (как меньше, так и больше общего пула).
   - **Автоматический выбор слов**, без отдельного поля и пояснений: используется `shuffled_cycles`. При числе заданий меньше числа уникальных слов берётся начало случайно перемешанного набора без повторов; при равенстве или базовом объёме — весь перемешанный набор один раз; при превышении — новые перемешанные циклы без одинакового слова на границе циклов (если в наборе более одного слова). При сохранении HTML-рецепта прежний ручной режим заменяется на `shuffled_cycles`. Реальный генератор тренировки в HTML не реализован.
   - **Время на слово**:
     - *«Без ограничения»* или ограничение в секундах. Таймер покрывает всё слово целиком.

4. **Предпросмотр и сохранение**:
   - Отображаются два счётчика: «Доступно уникальных слов в наборе» и «Заданий за тренировку».
   - Кнопка «Посмотреть слова» раскрывает список японских слов, чтений и переводов, входящих в набор.
   - При нулевом доступном пуле сохранение блокируется понятным сообщением об ошибке.

5. **Управление рецептами**:
   - Постоянный выбор рецепта радиокнопкой убран: рецепт для тренировки выбирается на `HOME.01` при запуске. Тап по телу карточки в RECIPE открывает просмотр RECIPE.02. Overflow-меню на карточке нет. Пользователь остаётся в конструкторе; диалог и автоматический переход на главную отсутствуют. «Назад» возвращает на главную.
   - Перестановка начинается долгим нажатием на тело карточки и продолжается перетаскиванием. Меню экрана, отдельного режима, ручек и «Готово» нет. Раскрытие состава не запускает перенос. В HTML удержание — 450 мс; движение более 8 CSS px до срабатывания отменяет ожидание и оставляет обычную прокрутку. Отпускание применяет порядок, Escape и отмена жеста возвращают исходный. Инструкций и видимых сообщений о позициях нет. Перетаскивание доступно только при пустом запросе поиска. В HTML доступны действия «Переместить выше/ниже» для экранного диктора и клавиатуры: обычно они визуально скрыты, при клавиатурном фокусе показываются. Результат озвучивается через невидимый live region. В Android запланированы нативные действия TalkBack; этот макет не реализует Android semantics.
   - Правка и удаление доступны с экрана просмотра RECIPE.02. Доступные действия перемещения меняют соседние позиции полного списка, в том числе при поиске; перетаскивание отфильтрованного списка отключено. Порядок хранится в памяти до перезагрузки макета.
   - **Требование для Android: анимированный захват при переносе.** После распознавания долгого нажатия карточка должна визуально отделиться от списка: плавно приподняться за счёт elevation/тени и небольшого изменения масштаба. Это обратная связь начала жеста, а не отдельный экран или режим с кнопкой завершения. До захвата обычная прокрутка не блокируется. Соседние карточки плавно освобождают место; отпускание и отмена сопровождаются плавным возвратом в итоговую или исходную позицию. Учитывать системные настройки анимаций; состояние захвата должно оставаться различимым и без движения. Конкретные параметры и стабильные API выбираются при реализации Android; HTML-эффект не является эталоном нативной анимации.
   - **Целевое поведение поиска:** при непустом запросе перестановка отключена как жестом, так и действиями доступности. Выдача остаётся результатом поиска, а не самостоятельным упорядочиваемым списком. Пустое открытое поле поиска перестановке не мешает. Очистка запроса возвращает полный список с сохранённым пользовательским порядком. При непустом запросе долгое нажатие не запускает перенос и не показывает сообщений; постоянная подсказка и действие очистки для переноса не нужны. Если пользовательские проверки покажут, что ограничение непонятно, допустимо отдельно добавить реакцию на удержание: «Перенос при поиске недоступен» / «Reordering is unavailable during search», без начала переноса. Это резервный вариант, не текущее требование. В текущем HTML жест уже отключён без сообщения, а отключение доступных действий при поиске ещё требует реализации.
   - Удаление сопровождается модальным подтверждением. Учебные материалы при этом не удаляются.

## 2. Экранная структура и макет

### Экран «Конструктор рецептов» (TRAIN, RecipesList)

```text
Назад     Рецепты                     [поиск]
Выберите или создайте                     кот-мастер
11 рецептов

Tobira · глава 10                              >
Учебник
20 заданий                  [30 с на слово]

Слова с кандзи N5                              >
Кандзи / JLPT · JLPT N5
Все N слов                  [20 с на слово]

        прокручиваемый список из 11 примеров
                                  [ + Создать ]
```

Поиск повторяет паттерн каталога: лупа в шапке открывает поле под заголовком; при открытии используется search_off. Поле и его фокус используют общие CSS-правила каталога и общую тему. «Очистить» сбрасывает запрос, оставляет поле открытым и возвращает в него фокус. Закрытие поиска и Escape в поле сбрасывают запрос и возвращают фокус лупе. Поле прокручивается вместе со списком; шапка остаётся доступной.

Фильтрация работает сразу по названиям на доступных языках и локализованным подписям всех источников, включая учебники, главы, JLPT и конкретные кандзи. Регистр, крайние и повторные пробелы, Unicode-ширина и ё/е не влияют на совпадение; все слова запроса должны встречаться в названии или составе. Японский ввод не перерисовывается посреди IME-композиции. Запрос сохраняется при переходе в редактор и обратно. Порядок карточек и позиция прокрутки сохраняются. Счётчик показывает найденные и общее количество; при отсутствии совпадений доступны подсказка и очистка, FAB создания остаётся видимой. Пустая библиотека имеет отдельное состояние.

Карточки имеют общую ширину и минимальную высоту 124 CSS px; высота растёт по содержимому. Внутренние поля — 12 CSS px. Радиокнопка выбора убрана: текстовая колонка занимает всю ширину карточки. Справа только название может иметь резерв под служебные действия доступности; состав и параметры используют оставшуюся ширину. Промежутки между блоками — 10 CSS px, отступ параметров от разделителя — 12 CSS px. Состав не имеет искусственной минимальной высоты. Название и материал переносятся без обрезки, включая длинные переводы. Заголовок 18, подпись материала 13, параметры 14. Параметры расположены в двух колонках, при увеличенном тексте — вертикально. Над списком показан подзаголовок «Создайте или откройте» / «Create or open», ниже — количество рецептов меньшим кеглем 13 CSS px (подзаголовок — 18 CSS px).

Нажатие на тело карточки открывает RECIPE.02. Hover-состояний нет: обратная связь при нажатии показывается только у отдельных элементов управления, а не всей карточки. Клавиатурный focus-visible сохранён. Название показано полностью; состав показан метками реальных источников и фильтров, полный редактор доступен через «Изменить рецепт». Для всего набора показано конкретное локализованное число слов, для ограниченной тренировки — число заданий; размер набора также доступен в редакторе отдельно от длины тренировки.

Метки состава — представление условий источника, а не слова, извлечённые из названия рецепта. Для личного источника условие `tag_ids` ссылается на реальные теги словаря; их названия разрешаются с русским языком подстановки. Остальные метки не создают новую сущность пользовательских тегов:

| Поля модели | Метка |
| --- | --- |
| `source_id` → `sources` / `sources_translations` | Название конкретного учебника, например «Tobira» или «Basic Kanji Book»; для личного источника — «Мой словарь» |
| `chapter_from`, `chapter_to` | Конкретная глава, закрытый диапазон или открытая граница: «Глава 10», «Главы 1–10», «С главы 3», «По главу 5» |
| `jlpt_level` | «Кандзи JLPT N5»; это классификация кандзи, не словарный уровень |
| `kanji_id` → `kanji` | Конкретный знак, например «Кандзи 日» |
| `word_id` → `words` | Полное написание учебной записи, включая выражения и предложения |
| Источник без ограничений | «Все источники» |

Каждый материал показан одной компактной меткой: название источника и его фильтры объединены через « · » (например «Tobira · Главы 3»). Цвет метки берётся по типу материала. Логика объединения источников по «или» сохранена в доступном описании без видимой строки. Источники объединяются без повторов слов. На карточке списка (RECIPE.W04.W01) показаны только первая метка материала и текст «Ещё N» (N — число скрытых материалов), без раскрытия в карточке — полный состав смотрят в RECIPE.02. Так высоты карточек остаются единообразными. Условия не теряются: они входят в текст метки материала. Метки и «Ещё N» не имеют самостоятельного действия. Переименование рецепта не меняет их; изменение фильтра меняет соответствующую метку. Название учебника разрешается через `language_tag`: запрошенный язык, базовый язык, русский, исходное название. В HTML личный источник обозначается существующим значением `book: 'personal'`; это не новый идентификатор в SQL. [Модель](../../database/recipes.md).

Обычные карточки используют общую нейтральную поверхность SurfaceContainer без внешней обводки. Между описанием и параметрами проходит тонкая разделительная линия. Метки имеют общие роли темы по полю модели: учебник — SecondaryContainer, кандзи/JLPT — PrimaryContainer, личный словарь — TertiaryContainer, главы и записи — SurfaceContainerHighest с парными On-ролями. Цвет не зависит от текста названия. Отдельных HEX-палитр конструктора нет.

Карточки сохраняют нейтральный фон SurfaceContainer и текст OnSurface без состояния «выбран». Кот-мастер остаётся в шапке. Время отображается обычным текстом со значком часов в строке параметров без цветной подложки, чтобы не выглядеть тегом состава. Иконки количества и времени используют OnSurfaceVariant. Без таймера показана текстовая подпись. [Роли палитры](../03-foundations/recipe-palette.md).

На карточке списка нет overflow-меню. Тап по телу карточки открывает экран просмотра RECIPE.02: оттуда «Изменить» ведёт в редактор, удаление — через меню шапки с подтверждением. Дублирование с карточки списка недоступно.

Создание — закреплённая Extended FAB «+ Создать» внизу справа, вне прокручиваемого списка. Кнопка не исчезает при прокрутке и не меняет подпись при сворачивании. В списке снизу зарезервировано 100 CSS px и scroll-padding: последний элемент можно полностью поднять над FAB. Пустой список сохраняет ту же FAB. Системная жестовая панель находится ниже области приложения. В Android использовать inset-aware Scaffold и стабильные Material3-компоненты; HTML не подменяет проверку нативных inset.

Демонстрационные рецепты: Tobira, глава 10; Tobira 1–10; N5; Tobira целиком; Basic Kanji Book целиком и глава 3; личные слова; N4; «Повторение для чтения» из двух учебников; слова с 日; «Большое повторение» из десяти источников (четыре диапазона Tobira, пять Basic Kanji Book и личный словарь). Пример с десятью источниками расположен вторым в списке; все его источники разрешаются в непустые выборки. Они используют реальные связи каталога и демонстрационный личный словарь. Изменения сбрасываются перезагрузкой страницы.

Верхний блок оставляет воздух перед списком: минимальная высота 112 CSS px, отступ до карточек 24 CSS px. Между карточками — 16 CSS px. Шапка содержит статичного [кота-мастера](../assets/mascot/cat-crafting-cards.png), собирающего карточки за столом. Файл с прозрачным фоном отображается 96 × 96; изображение декоративно и не получает фокус. Общая палитра применяется во всех фичах единого просмотрщика. Список RECIPE согласован; изменение HTML-макета не означает реализации конструктора в Android.

## 4. UI-компоненты и передача в Jetpack Compose

- `RecipeCard(plan, onOpen)`:
  - Тап по телу открывает просмотр; название и материал переносятся без обрезки. Число заданий и время показаны отдельно.
  - Overflow-меню на карточке отсутствует.
  - Постоянного выбранного состояния нет.
  - Без ViewModel, запросов к репозиторию и навигации внутри компонента.
- `RecipeListIntro(count)`: подзаголовок «Создайте или откройте», локализованное количество и декоративный кот-мастер, созданный по образцу каталога.
- `CreateRecipeFab(onClick)`: закреплённая подписанная Extended FAB вне списка с inset и отступом прокрутки.
- `RecipeMaterialRow(source, wordCount, onEdit, onRemove)`: плашка источника в редакторе с бейджем учебника/словаря.
- `RecipeLimitControl(title, isLimited, value, onToggle, onValueChange)`: выбор между безлимитным и числовым значением.
- `RecipeMaterialPickerModal(sourceDraft, catalogSources, onSave, onDismiss)`: модальное окно добавления/редактирования источника с динамической блокировкой глав.
- `RecipePreviewSection(uniqueWordsCount, trainingTaskCount, wordsList, onToggleList)`: сводка состава.

Все компоненты — чистые Compose-функции без прямого обращения к базам данных и ViewModel.
