# Конструктор: сквозная проверка установленного приложения с Room

## Среда и безопасность

Скрипт работает с реальным `app-debug.apk`, графом `KanjiApplication` и Room, без моков и прямых SQL-записей. Отказывается продолжать при наличии доступных нетестовых рецептов. Создаёт только записи с переданным ASCII-префиксом и удаляет их через UI (архивация).

## Сценарий

1. С главной открыть «Рецепты тренировок», создать A с материалом «По кандзи».
2. Создать B. UUID материалов различаются. Тап по телу открывает просмотр и **не** меняет `is_active` (постоянной радиокнопки нет).
3. Из просмотра A открыть «Изменить», переименовать, сохранить. UUID и материалы прежние, revision растёт.
4. Штатным `input touchscreen draganddrop` перенести B перед A; `is_active` не меняется от переноса.
5. `am force-stop` и повторный запуск: порядок, имена, revision и материалы совпадают.
6. Удалить B и A из просмотра (меню «Действия с рецептом…»). Список пуст; после повторного force-stop состояние остаётся пустым.

## Воспроизведение

```bash
python3 doc/verification/recipe-app-e2e.py \
  --adb "$HOME/Library/Android/sdk/platform-tools/adb" \
  --serial <device> --prefix E2E_YYYYMMDD \
  --output /tmp/kanji-recipe-app-e2e.json
```

Выбор рецепта для тренировки — на `HOME.01`, не в списке RECIPE. Исторический прогон 2026-11-05 с радиокнопкой не повторяется.
