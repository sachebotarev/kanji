# Конструктор: сквозная проверка установленного приложения с Room

Дата: 2026-11-05. Результат: **PASS**.

## Среда и безопасность

- Pixel 10 Pro, Android 17, `61020DLCH005EX`.
- Реальный `app-debug.apk`, `ru.mobui.kanji`, версия 1.0; установлен без очистки данных.
- До проверки основной пакет отсутствовал; на устройстве были отдельные инструментальные test-пакеты. Пользовательских рецептов в основном приложении не было.
- Работает обычный граф `KanjiApplication` и настоящие репозитории/Room `learning.db`, а не фикстуры dashboard.
- Созданы только записи `E2E_20261105_A` и `E2E_20261105_B`. После проверки обе удалены обычной командой интерфейса: в БД они архивированы, активных/доступных рецептов нет. Прямых SQL-изменений и сброса приложения не было.

## Сценарий и результат

1. С главной открыт список, создан A с материалом «По кандзи», без ограничения символов. Интерфейс показывает 2491 задание. В Room: локализованное имя `language_tag=ru`, тип материала `kanji`, UUID рецепта и материала.
2. Создан B через тот же интерфейс. UUID материалов различаются, первый рецепт остаётся активным. Нажатие текста B не выбирает его.
3. Через overflow открыт A, имя изменено на `E2E_20261105_A_edited`. UUID рецепта/материала прежние, revision увеличена с 1 до 2. Возврат в список происходит после успешной записи.
4. Радиокнопкой выбран B. В Room активен только B.
5. Штатной Android-командой `input touchscreen draganddrop` B перенесён перед A. В Room порядок `B(position=0), A(position=1)`; активный ID не изменился.
6. Приложение реально остановлено `am force-stop` и заново запущено. Повторно открыт список. Названия, порядок, revision, состав материалов и активный ID в БД совпадают полностью с состоянием перед остановкой; радио B отмечено.
7. Через меню и подтверждение удалён активный B. В БД он архивирован/неактивен; A доступен, но автоматически не выбран. Главная показывает «Тренировка не выбрана».
8. Удалён A. Список пуст. После повторного force-stop/запуска состояние остаётся пустым, оба тестовых рецепта архивированы/неактивны.

Каждое состояние сверялось с копией `learning.db` и её WAL через разрешённый для debug приложения `run-as`. Проверялся `PRAGMA quick_check`. БД не открывалась для записи в каталоге приложения. UI выбирался по тексту/content-description из штатной UI Automator hierarchy, координаты вычислялись из текущих bounds.

## Воспроизведение и свидетельства

[Скрипт](recipe-app-e2e.py) использует только Python stdlib и Android platform-tools, без новых библиотек/API приложения. Он отказывается продолжать при наличии доступных нетестовых рецептов. Один A можно передать уже созданным с тем же префиксом: именно так автоматизированный прогон продолжил начальную ручную проверку создания A.

```bash
python3 doc/verification/recipe-app-e2e.py \
  --adb "$HOME/Library/Android/sdk/platform-tools/adb" \
  --serial 61020DLCH005EX --prefix E2E_20261105 \
  --output /tmp/kanji-recipe-app-e2e.json
```

[Снимки состояния десяти контрольных точек](recipe-app-e2e-result.json) содержат только метаданные двух проверочных рецептов/материалов. Проверка чтения БД завершена без ошибок. Код приложения и зависимости в этом проверочном срезе не менялись; 59 инструментальных тестов dashboard и сборка/lint пройдены в [предыдущем срезе](recipe-library-android.md).

## Что эта проверка не подтверждает

Это один RU-сценарий с материалом «По кандзи» и реальной БД. Он не заменяет сквозную проверку каждого типа материала, полную RU/EN × light/dark × large-font матрицу и TalkBack. Проверена сохранность **записанных рецептов** после настоящей остановки процесса, но не восстановление **несохранённого черновика** после системного убийства фонового процесса. Force-stop и такое восстановление имеют разную семантику. Общий detekt остаётся незелёным. Сессии/исполнение рецептов и статистика не входят в сценарий.
