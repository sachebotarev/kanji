# Проверка модели БД для согласованных экранов

Дата: 2026-11-04. Область: главная, учебники, справочники, словарь, рецепты и общие селекторы. Исполнение тренировок и статистика исключены по решению пользователя.

## Вывод

Действующая Room v4 подходит как каталожная и словарная основа, но **не содержит тегов и рецептов**. Одних UI-изменений недостаточно. Исправленный проект добавочного DDL готов для последующего переноса в Room, но не установлен в Android. Версия базы и entities/DAO в этой задаче не менялись.

| Несоответствие | Исправление проекта |
|---|---|
| Не было исполняемого DDL тегов | personal-dictionary.sql: сущность, переводы, связи, индексы и проверки |
| Цвета sage/hex не соответствовали согласованным семи ролям | CHECK neutral/green/blue/violet/pink/orange/gold |
| SQLite NOCASE недостаточно для Unicode-дубликатов | name_key, уникальный в языке; NFKC/casefold вычисляет репозиторий |
| Архивирование тегов оставляло скрытые условия | Физическое удаление с CASCADE связей слов и материалов, без удаления самих записей |
| Таблицы выполнения и задания входили в прежний DDL | Удалены из текущей целевой модели |
| Скрытые режимы random_with_replacement/ANY-ALL и одиночный JLPT расходились с UI | Только shuffled_cycles; фасеты селектора временные, сохраняются выбранные ID |
| Материал мог ссылаться на источник неверного типа | CHECK/FK и проверки активного personal/textbook/book |
| Нулевая/чужая глава | Положительный номер и принадлежность выбранному учебнику |
| Активный архивный рецепт | CHECK и частичный уникальный индекс |
| Описание слов ошибочно подразумевало уникальность каждого поля | Существующая уникальность пары написание/чтение, предложения сохраняются |

## Воспроизводимая проверка

Из корня: `python3 doc/database/test_builder_schema.py`.

Тест создаёт **все таблицы и индексы из экспортированной Room v4**, затем применяет personal-dictionary.sql и recipes.sql в SQLite in-memory с включёнными FK. Результат: **6 тестов прошли**. Проверены мультиязычные переводы, ключи дубликатов, личная область тегов, цвета, главы, типы материалов, FK, активный выбор, положительные параметры, отсутствие таблиц выполнения тренировок, каскады без потери слов, rollback и OR/AND без дублирования строк.

Границы: это не Android MigrationTestHelper, не сравнение новой Room identity hash и не проверка реального DAO. В репозитории обязательны канонизация BCP 47/name_key, транзакционная проверка полного агрегата после изменения родителя, непустого результата, источников/архива, обновление revision и сохранение пользовательских данных. SQLite не гарантирует наличие хотя бы одного перевода/материала в промежуточном состоянии транзакции. Эти проверки нельзя считать реализованными только по DDL.
