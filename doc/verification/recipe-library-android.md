# Android: список рецептов, главная и платформенный перенос

## Подключение

Вход с главной открывает `RecipeBuilderRoute`. Собственные типизированные записи стека владеют `RecipeEditorRoute`, просмотром слова и управлением тегами. Приложение компонует содержимое каталога/словаря через callbacks; зависимости feature → feature отсутствуют. Личный отрицательный ID слова передаётся без изменения.

`RecipeLibraryViewModel` наблюдает интерфейсы каталога, личного словаря и рецептов. Порядок хранится в Room, query — в SavedStateHandle; вычислительный dispatcher передаётся через конструктор. Постоянной радиокнопки в списке нет: рецепт для тренировки выбирается на `HOME.01`. Поле `is_active` остаётся в схеме для сводки/fallback запуска; UI списка его не переключает. Отсутствие таймера не показывается как «0 минут».

Дублирование открывает несохранённую копию в отдельном редакторе: новые UUID рецепта/материалов, все переводы названия с суффиксом копии, revision 1 и неактивное состояние. Репозиторий списка не публикует копию; запись выполняется только по Save. Back без правок ничего не создаёт, восстановление сохраняет снимок и ID. [Контракт и проверки](recipe-copy-parity.md). Удаление подтверждается; удаление активного не выбирает соседний рецепт. Схема Room остаётся v5, миграции не добавлены.

## Перенос

- Источник — стабильный `Modifier.dragAndDropSource(transferData)`, получатель — `dragAndDropTarget` и запомненный `DragAndDropTarget`.
- Android/Compose распознаёт долгое нажатие, создаёт drag shadow, ведёт сеанс переноса и доставляет move/drop/end. Собственного pointer detector/движка переноса нет.
- Принимаются только события с `localState` текущего экземпляра списка; глобальный экспорт и разрешения передачи не включены.
- Прикладной адаптер `RecipeReorderState` хранит исключительно временный порядок UUID и положение внутри списка. `animateItem` перемещает соседние карточки; исходная карточка остаётся различимым приглушённым местом в списке. Системная тень независима от удаления исходного элемента из lazy-композиции.
- На краю запрашивается штатный `LazyListState.scrollBy`; скорость учитывает плотность экрана и длительность кадра. За пределами списка прокрутка прекращается. Сам LazyColumn не выполняет перестановку прикладной модели по Android DragEvent — эту небольшую часть реализует адаптер.
- Единственная команда сохранения порядка поступает на принятый drop. Изменение исходного списка во время сеанса переноса делает drop недействительным. Отмена/сброс вне области не пишет порядок; Back вызывает платформенный `View.cancelDragAndDrop()`.
- Тело карточки открывает просмотр; overflow на карточке списка нет. Поиск отключает источник переноса и команды доступности. `is_active` не меняется при переносе.
- Технический выбор и проверка версий через Context7: [решение](../decisions/platform-drag-and-drop.md).

## Проверка 2026-11-05

Pixel 10 Pro, Android 17, устройство `61020DLCH005EX`.

- `:app:assembleDebug`, `:feature:dashboard:assembleDebugAndroidTest`, `:feature:dashboard:lintDebug`, `:domain:catalog:test` — успешно; домен: 34 JVM-теста.
- `RecipeLibraryTest`: **12 тестов**, 69,223 с, без ошибок; включён путь несохранённой копии.
- Полный dashboard: **67 тестов**, 230,633 с, без ошибок; финальный прогон включает оформление ошибок полей.
- Хранилище: **8 тестов**, 54,149 с, без ошибок; включая удаление активного без автоматического выбора другого. Этот DAO-прогон выполнен для среза списка до замены UI detector; последующая замена касается только dashboard UI.

Проверенные сценарии:

1. Активный рецепт, точный порядок, запрет перестановки при поиске, удаление активного без выбора другого.
2. Несохранённая независимая копия, восстановление её ID/снимка, отсутствующий исходник, Back без публикации, busy, ошибка и повторная запись по Save.
3. Нажатие тела открывает просмотр; радиокнопки постоянного выбора и overflow на карточке нет; правка/удаление — с RECIPE.02.
4. NFKC-поиск по скрытым переводам, сохранение query и отключение accessibility reorder при поиске.
5. Реальный Android drag: принятый drop и ACTION_CANCEL без сохранения.
6. Непустой поиск не запускает системный перенос.
7. Список из 16 рецептов: перенос за первоначальный viewport, автоматическая прокрутка вниз и вверх до начала, сохранение ровно один раз на каждый drop, отсутствие потери/дублирования UUID.
8. Настоящий типизированный граф: возврат из карточки слова без потери названия и закрытие редактора только после записи.
9. Два последовательных создания получают отдельные навигационные владельцы, новые recipe/material UUID и пустое имя в новом черновике; после Save каждый раз возврат на список RECIPE.
10. Сводка главной следует изменению активного рецепта и очищается после его удаления.

`PlatformRecipeDrag.kt` вводит события через Android `UiAutomation.injectInputEvent`, а не Compose `performTouchInput`: последнее само по себе не доказывает работу системной drag session. В тестовом окружении продвигаются и реальные таймеры, и Compose clock. Перед повторным захватом координаты читаются после завершения анимации отмены.

## Границы

Тесты графа используют управляемые репозитории; Room проверяется отдельно. Дополнительно пройден [сквозной RU-сценарий установленного приложения с настоящей Room](recipe-app-e2e.md): создание/изменение/выбор/перенос, реальный force-stop/запуск и удаление. В том прогоне проверены записанные рецепты. Отдельный [EN-сценарий с несохранённым черновиком](recipe-process-death.md) прошёл после настоящего завершения фонового процесса и возврата через Recents; название/материал/параметр восстановились без записи в Room. Это не полная проверка вложенных селекторов/диалогов или дефицита памяти. Отдельно пройдена [визуальная матрица шести представлений конструктора](recipe-visual-matrix.md): RU/EN × светлая/тёмная тема × шрифт 100%/150%, 48 кадров финальной сборки. Полная матрица приложения и полный TalkBack не заявлены. В [срезе доступности](recipe-accessibility-android.md) на Android 17 AVD прошли 12 проверок списка/семантики и полный набор dashboard из 62 тестов (220,382 с); два системных drag-теста дополнительно прошли повторно. Тест повторного захвата прокручивает карточку в видимую область перед получением новых координат: старт из обязательной системной зоны жеста «Домой» недопустим. Android drag-сеанс, отмена без записи и автопрокрутка в обе стороны проверены без изменения продуктового обработчика и без отключения системных жестов. Общий detekt не проходит; его результат не выдаётся за успешный lint. Исполнение тренировок и статистика не реализуются.
