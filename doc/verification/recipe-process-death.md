# Несохранённый рецепт: восстановление после завершения фонового процесса

Дата: 2026-11-05. Результат: **PASS** для описанного сценария.

## Среда

Отдельный установленный AVD `Medium_Phone_API_37.0`, Android 17/API 37, `emulator-5554`, EN. Текущий `app-debug.apk`, настоящие `KanjiApplication`, навигационный граф и Room. Эмулятор запущен без окна и без сохранения snapshot. Телефон не использовался: там обнаружен несохранённый черновик Tobira, который не завершался и не удалялся.

## Сценарий

1. С главной открыт список и новый рецепт.
2. Введено `PROCESS_DRAFT_20261105`, добавлен материал «By kanji» без ограничения символов, выбран режим «Set a number», введено 17.
3. Снимки таблиц рецептов/переводов/материалов/их ограничений совпадают с исходными: форма ещё не публиковалась в БД.
4. Нажата системная Home, Activity оставлена в фоне. Выполнено `am kill --user current ru.mobui.kanji`. Отсутствие PID проверено явно.
5. Через **Android Recents** выбрана сохранённая задача приложения. Новый PID: `5709`, прежний: `5172`.
6. После повторного чтения репозиториев восстановлены редактор, название, добавленный материал и поле 17. Таблицы рецептов не изменились.
7. Back открыл диалог несохранённых изменений. Discard вернул в список без изменения БД.

Сравнивались отсортированные строки семи таблиц: `trainings`, `trainings_translations`, `training_sources`, `training_source_chapters`, `training_source_kanji`, `training_source_words`, `training_source_tags`. SHA-256 до создания, перед завершением процесса, после восстановления и после отмены одинаков:

```text
d3160e02a31bff4f4cc8e6a7ab92ee54992595931f8c0ec2093e9b70717dee39
```

Чтение — из временной копии БД с WAL; `PRAGMA quick_check` успешен. Ни SQL-записей, ни очистки приложения, ни force-stop в сценарии нет. Код приложения и зависимости не менялись.

## Воспроизведение

[Скрипт](recipe-process-death.py), [результат](recipe-process-death-result.json):

```bash
python3 doc/verification/recipe-process-death.py \
  --adb "$HOME/Library/Android/sdk/platform-tools/adb" \
  --serial emulator-5554 --output /tmp/kanji-process-death-result.json
```

Скрипт рассчитан на отдельный EN-эмулятор, начинает только с главной и не сохраняет проверочный рецепт. Восстанавливает именно существующую задачу из Recents, а не запускает новый экземпляр Activity.

Два первоначальных диагностических запуска использовали новый MAIN/LAUNCHER intent. В этой задаче уже был корневой Activity с другим исходным intent (`am start -n`); такой запуск добавлял ещё один стандартный Activity, показывая новую главную вместо возврата к сохранённому редактору. Это не доказательство потери saved state. Возврат через Recents устранил ошибку методики; дополнительный probe с одним названием и итоговый полный сценарий восстановились. Отдельного исправления production-кода не потребовалось.

## Платформенная основа и границы

Через Context7 проверена официальная документация Android Developers, `/websites/developer_android`:

- [Activity lifecycle](https://developer.android.com/guide/components/activities/activity-lifecycle): остановленный процесс может быть уничтожен системой; transient UI state восстанавливается через saved instance state/rememberSaveable.
- [Save UI states](https://developer.android.com/topic/libraries/architecture/saving-states): ViewModel сам по себе не переживает process death; нужны saved state или постоянное хранилище.

Использованы уже подключённые стабильные `rememberSaveable`, SavedStateHandle и Navigation; новые API, зависимости и experimental opt-in не вводились. Android самостоятельно сохраняет задачу/состояние Activity; собственной имитации сериализации в тесте нет.

Это настоящая смена процесса после команды платформы, а не StateRestorationTester или Activity.recreate. Однако это **не** воспроизведение реального дефицита памяти/работы LMK. Проверен основной EN-редактор с одним материалом и числовым параметром; открытый вложенный selector/dialog, черновик изменения существующего рецепта и большие наборы требуют отдельных сценариев. Force-stop, удаление задачи из Recents и пользовательский Discard имеют другую семантику и не обязаны восстанавливать черновик.

Остаются полная визуальная матрица, TalkBack, расширенные вложенные сценарии восстановления и общий detekt. [Сохранённые рецепты с реальной БД](recipe-app-e2e.md) проверены отдельно.
