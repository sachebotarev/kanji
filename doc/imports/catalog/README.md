# Первичная загрузка и выпуск каталога

Дата: 20 октября 2026 года. Подготовлены файлы; Android-загрузчик реализован в `:data:catalogdb`. См. [реализацию](../../implementation/catalog.md).

## Готовый пакет

`data/catalog/seed/` уже входит в существующий assets source set приложения через `data/catalog/`:

- `catalog.sqlite` — проверенная SQLite-база для первичного заполнения;
- `catalog.json` — тот же снимок таблиц с именами колонок, версиями формата, схемы и содержимого; предназначен для будущего транзакционного загрузчика;
- `manifest.json` — версии, количества строк, SHA-256 и размеры файлов, хеши исходных CSV, схемы и реестра ID.

В пакете: 214 ключей, 3001 знак (3000 кандзи + `々`), 2491 слово/выражение/предложение, 2491 русский перевод, два учебника, 829 мест изучения кандзи, 3955 учебных связей. Источники: `1 = Tobira`, `2 = Basic Kanji Book`. Личный источник при первичной подготовке не создаётся: он принадлежит пользователю и создаётся приложением.

Оба формата оставлены для выбора реализации загрузчика. При подключении к Android следует упаковывать только используемый формат, чтобы не хранить два экземпляра данных. Текущие чтения исходных CSV приложением не изменялись.

`catalog.sqlite` — обычный SQLite, **не готовая Room-база с identity hash**. Для `Room.createFromAsset` сначала нужно согласовать Room entities с этой схемой, создать эталон через Room и подготовить совместимый prepackaged-файл, включая служебные метаданные Room. Альтернатива — загрузить `catalog.json` в уже созданную Room-базу транзакцией. Автоматическое копирование файла поверх существующей базы запрещено.

## Идентификаторы

`identity-registry.json` — постоянный реестр. Не удалять и не генерировать заново после первого выпуска.

- Кандзи: Unicode code point, без NFKC и переиндексации.
- Ключ: номер Канси.
- Источник: постоянный положительный ID из реестра.
- Слово: постоянный положительный ID. Пара написания и чтения используется для сопоставления, но статистика ссылается на ID.
- Учебная связь: постоянный ID по тройке `(source_id, word_id, kanji_id)`. Исчезнувшие связи остаются в реестре, их номера не выдаются повторно.
- Первое назначение новых ID использует сортировку для воспроизводимости; последующие сборки только дописывают IDs после максимального номера за всю историю.

Новые пользовательские слова, источники и связи предлагается создавать с отрицательными ID, не пересекающимися с положительными ID поставляемого каталога. Существующие общие слова повторно не создавать: использовать их положительный ID. Это локальное пространство ID, не схема синхронизации нескольких устройств. При появлении синхронизации потребуется отдельный глобальный идентификатор/отображение локальных ID.

Исправление написания/чтения не сопоставляется автоматически с прежним ID: по умолчанию создаётся новая запись, прежняя архивируется. Для сохранения личности при доказанной опечатке нужно отдельное редакционное изменение реестра с журналом старой/новой пары и проверкой уникальности. Объединение дублей и перенос статистики требуют отдельной миграции; сборщик их не выдумывает.

## Повторная сборка и проверка

Из корня проекта, Python 3, только стандартная библиотека, без сети и локальных игнорируемых источников:

```sh
python3 doc/imports/catalog/build_seed.py --check
python3 -m unittest discover -s doc/imports/catalog -p 'test_*.py' -v
```

Повторная сборка неизменённого пакета:

```sh
python3 doc/imports/catalog/build_seed.py
```

После согласованных изменений CSV:

```sh
python3 doc/imports/catalog/build_seed.py --content-version 3 --update-registry
python3 doc/imports/catalog/build_seed.py --content-version 3 --check
```

Рассмотреть diff реестра и отчётов перед выпуском. Если появились новые записи без `--update-registry`, сборка завершается ошибкой. Изменение существующей версии содержимого и понижение версии запрещены. `--initialize-registry` допускается только один раз, если файла реестра ещё нет. Пакет, реестр и отчёты коммитятся вместе.

`--check` сравнивает JSON, схему, все строки SQLite, целостность, внешние ключи и хеши. Физические байты SQLite могут отличаться между версиями движка; хеш проверяется по реально поставляемому файлу, содержимое — независимо от физического расположения страниц.

## Дополнения к согласованной модели

Схема: [schema.sql](schema.sql). Основные таблицы и связи сохранены.

1. `catalog_metadata(singleton, schema_version, content_version)`: позволяет отличить изменение структуры от изменения наполнения и применить обновление один раз. Версия схемы сейчас 1, содержимого — 2. `PRAGMA user_version=1` также фиксирует схему SQLite.
2. `words.is_archived`, `sources.is_archived`: устаревшая запись может исчезнуть из актуального интерфейса, сохраняя ID для статистики и личных ссылок. Прежние слова не удаляются из реестра; сборщик включает их как архивные, если они исчезли из всех CSV. Удаление учебной связи само по себе не архивирует слово, если оно остаётся в другом источнике. Для слов, добавленных пользователем, архивный статус каталога не должен скрывать личную связь автоматически.
3. `UNIQUE(source_id, kanji_number)` в `source_kanji`: защищает порядок учебника от назначения одного номера двум разным знакам. Номер и глава по-прежнему не являются идентичностью кандзи.
4. Индексы по ключу, главе, связям и чтению: для согласованных экранов поиска и фильтрации, без изменения смысла данных.
5. `language_tag COLLATE NOCASE` в таблицах переводов: запрещает дубли вроде `ru` и `RU`, сохраняя возможность тегов `pt-BR`. Новые языки — новые строки, не колонки.
6. Для общих слов и источников удаление связанных данных ограничено `RESTRICT`; удаление перевода кандзи/ключа вместе с родительским справочником — `CASCADE`, как предусмотрено моделью. Штатные обновления каталога не удаляют слова, кандзи и ключи физически.

Это заготовка схемы первоначального создания, а не миграция уже выпущенной пользовательской базы.

## Что потребуется Android-загрузчику

Первичная установка: создать схему, проверить manifest и заполнить таблицы одним атомарным действием до открытия каталога. Личные записи и таблицы статистики создаются отдельно своей логикой.

Обновление: мигрировать схему, если требуется, затем проверить пакет и применить актуальный снимок по ID одной транзакцией; версия содержимого записывается последней в той же транзакции. Возврат после сбоя безопасен. Новый полный снимок позволяет пропускать версии наполнения; миграции схемы всё равно должны иметь путь от каждой поддержанной версии.

Нельзя импортировать снимок путём очистки всех таблиц, применять `INSERT OR REPLACE` к родительским записям или вызывать destructive migration пользовательской базы. Использовать обновление существующей строки и вставку отсутствующей. JSON — полный снимок управляемой части каталога, не команда заменить пользовательскую БД.

- Обновлять поставляемые положительные слова/источники, не затрагивать пользовательские отрицательные записи.
- Синхронизировать только связи двух поставляемых источников; связи личного источника сохранять.
- Убирать отсутствующие актуальные учебные связи в правильном порядке: `source_words`, затем `source_kanji`. Статистика не должна ссылаться на эти изменяемые связи, номер главы или позицию.
- Архивные слова сохранять с прежним ID и последними доступными переводами/разбиениями, если они уже есть на устройстве; отсутствие перевода архивной записи в новом снимке не означает удалить старый перевод.
- Не удалять кандзи/ключи, на которые могут ссылаться личные данные и история. Если будущий выпуск изменит их состав, нужен явный план совместимости, а не только diff снимка.
- Данные завершённой попытки сохранять с `word_id`/`kanji_id`, версией каталога и снимком задания. Настоящее объединение/разделение записей требует отдельной карты миграции.
- Политика конфликтов пользовательского редактирования общих переводов должна быть определена до редактора «Моего словаря»: данный пакет не даёт права перезаписывать пользовательские варианты.

Настоящие таблицы статистики ещё не реализованы. Сохранение границ импорта на устройстве проверяет `CatalogInstallationTest` на личных записях и контрольной таблице статистики; см. [реализацию](../../implementation/catalog.md). Семь офлайн-тестов проверяют необходимые основы: стабильность ID при перестановке строк, переносе главы/порядка, исправлении перевода, добавлении, архивировании, обнаружение конфликтов и ограничения реальной SQLite-схемы.

## Чтения и исходные привязки

`word_reading_parts` пока пустая: в CSV есть части чтения, но нет достоверных границ соответствующих частей написания. Приписывать очередное чтение очередному символу некорректно, например для неделимых сочетаний или каны рядом с кандзи. Полное чтение каждого слова загружено в `words.reading`; исходные 3908 строк с разбиениями сохранены в [reading-parts-candidates.json](reading-parts-candidates.json) со ссылками на исходный файл/строку через `source_id`. Эти редакционные материалы находятся в `doc/` и не упаковываются.

Три точные повторные учебные связи объединены, разные привязки одного слова сохранены. В [validation.json](validation.json) перечислены 53 контекстных связей, где изучаемый знак не входит буквально в слово (например, слова с графическим компонентом изучаемого кандзи). Они не удаляются и не считаются ошибками импорта: это сохранённые учебные связи источника, а не утверждение о буквальном вхождении знака.

Русские переводы загружены; отсутствие английского перевода явно представлено отсутствием строки. Будущий слой чтения применяет русский fallback. Названия Tobira и Basic Kanji Book берутся из `original_title`, поскольку отдельных переводов названий пока нет. Условия происхождения данных сохраняются в существующем `data/catalog/NOTICE.txt` и документации исходников.

Версия содержимого 2: русское значение `々` сокращено до «знак повтора» по согласованию с пользователем; ID 12293, чтения, связи и реестр ID не изменились.
