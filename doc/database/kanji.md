# Таблицы кандзи

Статус: проект модели данных. Дата: 20 октября 2026 года.

Источник первоначального заполнения — [`kanji.csv`](../../data/catalog/kanji.csv), 3000 кандзи и знак повтора `々` (3001 запись). Типы указаны для SQLite/Room. Названия таблиц и полей — на английском, в `snake_case`. Модель учитывает [обязательную многоязычность](../implementation/localization.md): общие свойства, японские чтения и переводы значений хранятся отдельно.

## Таблица `kanji`

Одна строка — один исходный знак Unicode.

| Field | SQL type | Constraints | CSV column | Описание |
| --- | --- | --- | --- | --- |
| `id` | `INTEGER` | `PRIMARY KEY`, `NOT NULL` | `id` | Кодовая точка Unicode десятичным числом; без автогенерации. |
| `symbol` | `TEXT` | `NOT NULL`, `UNIQUE`, `CHECK (length(symbol) = 1)` | `Кандзи` | Исходный символ кандзи. |
| `stroke_count` | `INTEGER` | `NOT NULL`, `CHECK (stroke_count > 0)` | `Количество черт` | Нормативное число черт. |
| `radical_id` | `INTEGER`, допускает `NULL` | `FOREIGN KEY REFERENCES radicals(id)` | `Ключ` | Номер ключа Канси; отсутствует у `々`. |
| `is_kyoiku` | `INTEGER` | `NOT NULL`, `CHECK (is_kyoiku IN (0, 1))` | `Входит в Кёику кандзи` | Принадлежность к кёику-кандзи. |
| `is_joyo` | `INTEGER` | `NOT NULL`, `CHECK (is_joyo IN (0, 1))` | `Входит в Дзёё кандзи` | Принадлежность к дзёё-кандзи. |
| `is_jinmeiyo` | `INTEGER` | `NOT NULL`, `CHECK (is_jinmeiyo IN (0, 1))` | `Входит в Синмэйё кандзи` | Принадлежность к дополнительному перечню именных знаков. |

**Первичный ключ: `id`.** В Kotlin — `Int`; признаки списков — `Boolean`, в SQLite — `0`/`1`. Дополнительное ограничение таблицы: `CHECK (is_kyoiku = 0 OR is_joyo = 1)`.

При импорте проверяется `id == codePoint(symbol)`. Знак должен состоять из одной допустимой кодовой точки Unicode, а не обязательно одного UTF-16 `Char`. NFKC-нормализация запрещена: совместимые и вариантные знаки сохраняют свои идентификаторы.

## Связь с ключами

`kanji.radical_id → radicals.id`: каждому обычному кандзи соответствует один ключ; один ключ может относиться ко многим кандзи. На `kanji.radical_id` создаётся неуникальный индекс. Удаление используемого ключа и изменение его номера запрещены (`ON DELETE RESTRICT`, `ON UPDATE RESTRICT`).

Пример: `一` имеет `id = 19968`, `radical_id = 1` и ссылается на ключ `一` с `radicals.id = 1`. Здесь хранится основной словарный ключ, а не перечень всех графических компонентов знака.

`々` хранится отдельной записью: `id = 12293` (`U+3005`), `stroke_count = 3`, все три признака списков — `false`. Это знак повтора предыдущего кандзи. Ключ и собственные онъёми/кунъёми отсутствуют: соответствующие ячейки CSV пустые, строки в `kanji_readings` не создаются. Пустой ключ импортируется как `NULL`, не `0`. Ограничение таблицы: `CHECK ((id = 12293 AND radical_id IS NULL) OR (id <> 12293 AND radical_id IS NOT NULL))`. Слова ссылаются на `kanji.id = 12293` обычным внешним ключом; отсутствие ключа Канси не влияет на эту связь.

Описание справочника ключей: [radicals.md](radicals.md).

## Таблица `kanji_translations`

Название следует общему правилу: полное имя основной таблицы + `_translations`.

Одна строка — одно значение или описание употребления кандзи на одном языке. Несколько значений из CSV не объединяются в строку с разделителем `|`.

| Field | SQL type | Constraints | Описание |
| --- | --- | --- | --- |
| `kanji_id` | `INTEGER` | `NOT NULL`, `FOREIGN KEY REFERENCES kanji(id)` | Кандзи, которому принадлежит значение. |
| `language_tag` | `TEXT` | `NOT NULL`, `CHECK (length(trim(language_tag)) > 0)` | Языковой тег: `ru`, `en` и другие. |
| `position` | `INTEGER` | `NOT NULL`, `CHECK (position >= 1)` | Порядковый номер значения для данного кандзи и языка, начиная с 1. |
| `meaning` | `TEXT` | `NOT NULL`, `CHECK (length(trim(meaning)) > 0)` | Значение или краткое описание употребления. |

**Составной первичный ключ: (`kanji_id`, `language_tag`, `position`).** Позиция задаёт порядок показа, а не идентичность значения между языками: переводы на разных языках могут иметь разное число значений.

Столбец `Названия на русском` разделяется по `|`; каждый элемент импортируется отдельной строкой с `language_tag = 'ru'` и исходным порядком. Отсутствие перевода означает отсутствие строк для языка. При отображении используется запрошенный язык с подстановкой русского при отсутствии перевода, согласно общему правилу проекта. Языковые теги приводятся к единому согласованному формату без дубликатов, различающихся только регистром.

## Таблица `kanji_readings`

Принято решение хранить чтения отдельной таблицей: у кандзи несколько чтений, каждое должно быть доступно для поиска и использования в тренировках. Массивы JSON и строки с разделителем в `kanji` не используются.

Одна строка — одно японское чтение кандзи. Чтения относятся к изучаемому японскому языку и не меняются при переключении языка интерфейса.

| Field | SQL type | Constraints | Описание |
| --- | --- | --- | --- |
| `kanji_id` | `INTEGER` | `NOT NULL`, `FOREIGN KEY REFERENCES kanji(id)` | Кандзи, которому принадлежит чтение. |
| `reading_type` | `TEXT` | `NOT NULL`, `CHECK (reading_type IN ('on', 'kun'))` | `on` — онъёми, `kun` — кунъёми. |
| `position` | `INTEGER` | `NOT NULL`, `CHECK (position >= 1)` | Порядок чтения внутри типа, начиная с 1. |
| `reading` | `TEXT` | `NOT NULL`, `CHECK (length(trim(reading)) > 0)` | Чтение с сохранением исходной каны, точек и дефисов. |

**Составной первичный ключ: (`kanji_id`, `reading_type`, `position`).**

Столбец `Верхнее чтение` импортируется с типом `on`, `Нижнее чтение` — с типом `kun`. Непустые ячейки разделяются по `|` с сохранением порядка. Пустая ячейка означает отсутствие строк соответствующего типа, а не пустое чтение. Нанори в исходном CSV отсутствуют и не подмешиваются в эти типы.

## Целостность и импорт

- Сначала импортируется `radicals`, затем `kanji`, значения и чтения. Неизвестный непустой `radical_id` — ошибка импорта. Пустой ключ допустим только у `々`.
- Удаление кандзи удаляет связанные значения и чтения (`ON DELETE CASCADE`); изменение `kanji.id` запрещено (`ON UPDATE RESTRICT`).
- Булевы значения CSV `true`/`false` преобразуются в `1`/`0` без неявных значений по умолчанию.
- Сначала применяется CSV-парсер, затем разделитель `|` для многозначных ячеек. В БД хранятся отдельные значения и чтения.
- Добавление языка требует новых строк значений, а не изменения схемы или бизнес-логики. Русские значения из CSV составляют основной набор; их наличие не означает полную академическую сверку.
- Это описание будущей БД; создание таблиц и методов доступа выполняется отдельным этапом.

Подробности исходного каталога и его ограничений: [kanji-catalog.md](../implementation/kanji-catalog.md).
