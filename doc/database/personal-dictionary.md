# Личный словарь: целевая модель для согласованного UI

Основа: [слова](words.md), [согласованные экраны](../design-system/05-screens/dictionary/README.md), [контракт переноса](../implementation/approved-ui-handoff.md).

Room хранит личные записи в общей таблице `words`, переводы `words_translations`, части чтения, связи личного источника и теги. Entities/DAO и транзакционный репозиторий реализованы; интерфейс тегов подключён. [personal-dictionary.sql](personal-dictionary.sql) описывает ограничения SQL, экспорт Room — фактические таблицы, `RecipeChecks.kt` — дополнительные проверки. Миграции не создаются: невыпущенная база заменяется с потерей старых локальных данных. Исполнение тренировок — отдельно в [trainings.md](trainings.md).

## Записи и переводы

- Личная запись: `is_user_created=1`, не архивная, связана с реальным источником `source_type='personal'`. Знак ID сам по себе не определяет происхождение.
- Написание и чтение не уникальны по отдельности: используется существующая уникальность **пары** `written_form, reading`. Слова, выражения и предложения сохраняются полностью, без обрезания до одного слова.
- Переводы имеют составной ключ `(word_id, language_tag)`. BCP 47 канонизируется до записи; пользовательские данные не зависят от языка UI. Поддерживаемый выбор языков текущего макета RU/EN не означает ограничение схемы двумя языками. Существующие другие языки не теряются.
- Основное поле редактирует только перевод текущего языка. Другие переводы меняются на отдельном экране, но сохраняются с записью одной транзакцией. Отображаемый русский fallback не становится автоматически новым переводом.
- Удаление личного слова использует действующее архивирование; каталожные записи read-only. Запросы фильтров всегда исключают архивные слова/источники.

## Теги

`dictionary_tags` — стабильный ID, цвет, позиция и timestamps, без переводимого названия. Разрешены ровно семь идентификаторов цвета: `neutral`, `green`, `blue`, `violet`, `pink`, `orange`, `gold`; default `neutral`. Не использовать hex и несогласованные sage/ochre/plum: цвет — ссылка на тематическую палитру с light/dark-парами.

`dictionary_tags_translations` — `(tag_id, language_tag)`, название 1–60 символов и `name_key`. Ключ вычисляет репозиторий как NFKC → обрезка крайних пробелов → Unicode case folding. Уникальность `(language_tag, name_key)` защищает от дубликатов названий на одном языке. SQLite `NOCASE` не нормализует кириллицу; одной такой collation недостаточно. BCP 47 также проверяется/канонизируется в domain, не SQL-проверкой непустоты. При переименовании проверять ключ, кроме собственного ID.

Названия: точный язык → базовый язык → русский → существующее имя с детерминированным порядком языков. Новое имя создаётся на текущем языке; не требуется выдуманный русский перевод, если пользователь ввёл только английский.

`word_tags` — многие-ко-многим с PK `(word_id, tag_id)`. SQL-триггеры запрещают назначать тег неактивной или каталожной записи. При архивировании слова старые связи могут остаться для восстановления, но не участвуют в выдаче.

Тег удаляется физически: FK CASCADE удаляет переводы и связи слов/материалов, не слова и не рецепты. В текущем этапе нет исторических тренировок, ради которых нужно архивирование тегов. Архивный тег без очистки связей запрещён как замена удаления: он оставлял бы скрытые условия материала. Удаление последнего тега-фильтра снимает ограничение, как в HTML.

## Транзакционность

Назначение тегов записи временное до «Выбрать», вся запись — временная до сохранения. Созданный внутри назначения тег остаётся частью черновика. При сохранении: слово, переводы, новые теги, их переводы и связи записываются атомарно; отмена ничего не публикует. Управление общим набором тегов — отдельное явное действие с немедленным сохранением CRUD.

Одно состояние выбора используется в словаре, редакторе и материале рецепты; получатель результата и область кандидатов передаются явно. Черновик материала не меняет глобальный фильтр словаря.

## Запросы

- Кандидаты: активные личные `words` с `EXISTS` связи активного личного источника; не соединять выдачу так, чтобы размножались строки.
- Теги: пустой набор не ограничивает; иначе `EXISTS word_tags WHERE word_id=words.id AND tag_id IN (...)` — ИЛИ.
- Кандзи: пустой набор не ограничивает; иначе существует хотя бы один выбранный знак в написании — ИЛИ. Теги, кандзи и поиск пересекаются по И. Поиск включает написание, чтение и перевод с языковым разрешением.
- Использовать параметризованные запросы/подготовленные предикаты, не строковую вставку пользовательского ввода. Учитывать SQLite bind-limit для больших наборов ID.
- Общий каталог объединяет личные и учебные записи, а область учебника исключает личные. Дедупликация показа по нормализованной паре не удаляет исходные записи или связи.

## Проверка перед реализацией

Применить DDL поверх экспортированной Room 1, затем проверить FK, цвета, Unicode-дубликаты, запрет каталоговых тегов, каскадное удаление, rollback черновика, OR/AND, сохранность переводов и активных личных записей. В Android нужны реальные Room entities/DAO, схема новой версии и проверка установки/обновления. Наличие SQL в `doc/` не означает готовое хранилище тегов.
