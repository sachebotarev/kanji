# Словарь слов и источники

Статус: согласованная модель БД; подготовлен пакет первичного заполнения. Дата: 20 октября 2026 года.

Словарь общий для всех книг, учебников и пользовательского «Моего словаря». **Словарная запись может быть отдельным словом, выражением или полным предложением, если это необходимо для обучения.** Название `words` условное и не ограничивает запись одним словом. Источники ссылаются на существующие записи. Все типы ниже — SQLite; если не указано иное, поля обязательны (`NOT NULL`). Переводы отделены согласно [правилу многоязычности](../implementation/localization.md). Русский — основной язык и язык подстановки.

## `words`

Одна запись — уникальная пара написания и полного японского чтения.

| Field | SQL type | Назначение |
| --- | --- | --- |
| `id` | `INTEGER` | Первичный ключ, внутренний стабильный идентификатор. |
| `written_form` | `TEXT` | Полное написание слова, выражения или предложения. |
| `reading` | `TEXT` | Полное японское чтение записи. |
| `is_archived` | `INTEGER` | 0/1, архивная запись скрыта из активных списков. |
| `is_user_created` | `INTEGER` | 0/1, неизменяемый признак ручного создания, по умолчанию 0. Только 1 разрешает пользовательское изменение/удаление. |

**Первичный ключ: `id`. Обязательное ограничение: `UNIQUE (written_form, reading)`.** Написание и чтение не могут быть пустыми. Одинаковое написание с разными чтениями хранится отдельно, например `一日 / いちにち` и `一日 / ついたち`. Перевод и источник в уникальность не входят.

### Обязательное правило объединения данных

Законченные фразы, предложения и значимые формы употребления не считаются ошибками или дублями только из-за наличия частиц, окончаний или нескольких слов. Например, `本当ですか`, `目を覚ます`, `来ない`, `住んでいる`, `知っている` допустимы. Приведение к словарной форме применяется там, где оно действительно необходимо, без потери учебного смысла. Незавершённые шаблоны с заполнителями и условные скобки в написании удаляются или исправляются по согласованным правилам.

1. При импорте проверяются написание и чтение.
2. По паре `written_form + reading` ищется существующее слово.
3. При совпадении используется существующий `id`, добавляется связь с источником.
4. При отсутствии создаётся новое слово. Ограничение уникальности БД защищает также от параллельного создания дублей.

Различия записи могут скрывать смысловые дубли: `大変（な） / たいへんな` и `大変な / たいへんな`. При реализации импорта должны быть определены единые правила подготовки данных и проверка возможных дублей. Автоматически удалять скобки, менять кану, применять NFKC или объединять похожие слова нельзя без отдельного обоснованного правила. Исходные данные сохраняются для проверки.

## `words_translations`

| Field | SQL type | Назначение |
| --- | --- | --- |
| `word_id` | `INTEGER` | Внешний ключ → `words.id`. |
| `language_tag` | `TEXT` | Языковой тег, например `ru` или `en`. |
| `translation` | `TEXT` | Перевод или несколько значений текстом. |

**Первичный ключ: (`word_id`, `language_tag`).** Тег и перевод непустые; теги используют единый согласованный формат без дубликатов по регистру. Отсутствие перевода — отсутствие строки. Новая формулировка перевода не создаёт новое слово. Расхождения переводов при импорте сохраняются как конфликты для согласования, существующий перевод молча не перезаписывается. Формат хранения конфликтов определяется при реализации импорта.

## `word_reading_parts`

| Field | SQL type | Назначение |
| --- | --- | --- |
| `word_id` | `INTEGER` | Внешний ключ → `words.id`. |
| `position` | `INTEGER` | Порядок части, начиная с 1. |
| `written_part` | `TEXT` | Непустая часть написания, может включать несколько символов. |
| `reading_part` | `TEXT` | Непустое чтение этой части. |

**Первичный ключ: (`word_id`, `position`).** Части идут по порядку и вместе воспроизводят полное написание и чтение слова. Например, `一月`: `一 → いち`, `月 → がつ`. Допускаются неделимые сочетания вроде `一人 → ひとり`. Если достоверного разбиения нет, строк частей нет; полное чтение остаётся в `words`. Японские чтения не зависят от языка интерфейса.

## `sources`

| Field | SQL type | Назначение |
| --- | --- | --- |
| `id` | `INTEGER` | Первичный ключ. |
| `source_type` | `TEXT` | `textbook`, `book` или `personal`. |
| `original_title` | `TEXT` | Непустое исходное название источника. |

Для подготовленных учебников создаются ровно два источника: `Tobira` и `Basic Kanji Book`. Тома одного учебника не становятся отдельными источниками: нумерация кандзи и глав сохраняется сквозной. Номер тома не входит в ключи связей. Количество будущих источников не ограничено моделью. «Мой словарь» — источник типа `personal`, использующий общий словарь слов. Его системное название в интерфейсе берётся из ресурсов локализации, а не из текста, используемого как идентификатор. Название книги само по себе не является уникальным идентификатором издания.

## `sources_translations`

| Field | SQL type | Назначение |
| --- | --- | --- |
| `source_id` | `INTEGER` | Внешний ключ → `sources.id`. |
| `language_tag` | `TEXT` | Языковой тег. |
| `title` | `TEXT` | Непустое переведённое название. |

**Первичный ключ: (`source_id`, `language_tag`).** Таблица используется при наличии переводных названий. При отсутствии запрошенного перевода проверяется русский; если переводов нет, показывается исходное название.

## `source_kanji`

Основное место изучения кандзи в конкретном источнике; номер и раздел не повторяются для каждого слова.

| Field | SQL type | Назначение |
| --- | --- | --- |
| `source_id` | `INTEGER` | Внешний ключ → `sources.id`. |
| `kanji_id` | `INTEGER` | Внешний ключ → `kanji.id`. |
| `kanji_number` | `INTEGER` | Положительный сквозной номер кандзи в источнике, `CHECK (kanji_number > 0)`. |
| `chapter_number` | `INTEGER` | Положительный номер главы в источнике, `CHECK (chapter_number > 0)`. |

**Первичный ключ: (`source_id`, `kanji_id`).** Каждый кандзи изучается в конкретном источнике ровно один раз. Его сквозной номер и номер главы — два отдельных обязательных числовых поля. Поле `section` заменено на `chapter_number`; строки вроде «Tobira I, глава 3» в БД не хранятся. При импорте из CSV извлекается число главы, том не создаёт новый источник. Подпись «глава» локализуется в интерфейсе.

Пример: кандзи `月` имеет отдельную запись `source_kanji` для Tobira и отдельную для Basic Kanji Book; номера кандзи и главы у этих записей могут различаться. Повторение уже изученного кандзи в тексте не создаёт ещё одну запись его изучения. При противоречивых номерах или главах для одной пары (`source_id`, `kanji_id`) импорт сообщает о конфликте, а не перезаписывает данные.

## `source_words`

| Field | SQL type | Назначение |
| --- | --- | --- |
| `id` | `INTEGER` | Первичный ключ. |
| `source_id` | `INTEGER` | Внешний ключ → `sources.id`. |
| `word_id` | `INTEGER` | Внешний ключ → `words.id`. |
| `kanji_id` | `INTEGER`, допускает `NULL` | Изучаемый кандзи; без привязки, например в «Моём словаре», — `NULL`. |

При заполненном `kanji_id` составной внешний ключ (`source_id`, `kanji_id`) ссылается на `source_kanji`. Для него также действует связь с `kanji.id` через `source_kanji`.

Повтор одинаковой связи запрещён. Для заполненного кандзи — уникальность (`source_id`, `word_id`, `kanji_id`); для `NULL` — отдельный уникальный частичный индекс (`source_id`, `word_id`) с условием `kanji_id IS NULL`. Обычного составного `UNIQUE` недостаточно для предотвращения повторов с `NULL` в SQLite.

Одна и та же пара «написание + чтение» хранится в `words` единожды и имеет один набор переводов по языкам, независимо от числа источников и связей. Все привязки слова к разным кандзи сохраняются. Например, `一月` имеет одну запись в `words`, но связи с `一` и `月` в источнике. Первое изучение определяется по минимальному `kanji_number` среди связей слова в выбранном источнике; при необходимости повторные появления также доступны. Это первое изучение по данным привязок, а не доказательство первого появления слова в тексте книги. Номер главы не дублируется в `source_words`: он получается через `source_kanji.chapter_number`. Одно слово может иметь несколько связей с одним учебником через разные изучаемые кандзи; повтор той же связи не добавляется. Отдельный учёт всех текстовых появлений слова в разных разделах не требуется.

## Ручное создание — 21 октября 2026

Реализован [личный словарь](../implementation/personal-dictionary.md). Происхождение хранится в самой записи, независимо от источников, ID и языка. Пользовательские операции не меняют слова каталога. Совпадение с активной парой при ручном создании/изменении отклоняется без перезаписи; это отдельный сценарий от правил объединения импортируемого содержимого. Удаление ручного слова архивирует запись и снимает личные связи; повторное создание той же архивной ручной пары восстанавливает ID. Версия Room 2 добавляет признак без удаления существующих данных.
